# MaaS 文档任务切换与回退演练

2026-11-18 · [共库迁移 Issue #62](https://github.com/WTaoGitHub/cybercafe-maas/issues/62)

统一入口接收新文档任务时，历史任务、文件和用量留在各自原库。数据库迁移 `013` 支持按逻辑模型冻结新受理，并在目标库登记从其他库转来的幂等键保留记录。旧任务的 ID、模型修订、状态、文件路径、TTL 和收据都按原记录查询。此流程适用于异步文档任务。

| 请求 | 原受理入口 | 另一库的入口 |
| --- | --- | --- |
| 已受理的原请求和原 `Idempotency-Key` | 返回 `200` 与原 ID 和 `Location`，包括旧库被冻结后 | 返回 `409 IDEMPOTENCY_OTHER_STORE`，应在原入口以原请求取回回执 |
| 同项目换内容复用原本地键 | `409 IDEMPOTENCY_CONFLICT` | 键已保留时返回 `409 IDEMPOTENCY_OTHER_STORE` |
| 新文档任务 | 冻结时返回 `503 MODEL_SUBMISSIONS_CLOSED` | 完成切换后接受新键和在该入口上传的文件 |
| 任务、用量、文件查询 | 原 owner 项目保持可查询，文件 TTL 仍生效 | 按本库 ID 查询。现有 API 不跨库寻找任务或文件 |

键保留范围与现有幂等范围相同，为 `(project, Idempotency-Key)`。目标库发现与现存任务撞键时，整体拒绝导入并保持目标冻结，已经存在的任务不受影响。导出涵盖所有已受理文档任务，包括失败、取消及文件过期的任务。换新键会被视为另一笔提交，不能用它绕过原请求的重试保护。

同一凭据在两侧映射到不同项目时，先核实凭据相同，再在用于导入的清单副本中把该凭据的项目映射到目标项目。保留原清单和历史任务归属，核对两份清单仅有项目字段变化，并由 `activate` 在同一事务内检查目标项目的键冲突。回退时将回退清单中的新文档任务键映射回原项目。

## 正切演练顺序

1. 准备原文档库与统一库的连接配置、各自的 artifact 目录、项目绑定和备份。先用独立库恢复同一检查点的数据库与文件，核对成功、失败、文件过期、结果字节和原用量收据。备份窗口按既有方式停止对备份范围的写入和文件清理，再配对保存数据库与 artifact。
2. 两侧 API 和执行器都使用支持 `013` 的版本，按现有迁移机制应用新增表。先冻结目标库的文档新提交，再将候选文档模型开放给测试调用方检查。冻结与任务受理共用库内锁。原图片模型仍可在统一库接单。
3. 冻结原库的文档新提交，在旧代理启用下文的历史入口规则。保留原任务 GET、用量、下载和原键 POST 回执。原执行器继续处理已受理的队列。核对等待、在途、同步探针和 `UNKNOWN`，保留未完成上传的原入口及 artifact 清单。
4. 原库排空后导出键清单。从该次冻结的正确源库获取文件，在目标库保持冻结的状态下核对来源、模型与条数，然后执行 `activate`。读取表和完整受理操作验证目标已接掌写入。过渡期间保持单侧接收新的文档任务。
5. 原入口重试和历史读取通过后，新文档提交使用统一入口。在旧入口已上传但未提交的文档先核对是否已受理。确认无任务之后，才在当前入口重新上传并提交。切换期间记录请求的原入口、项目、键及已返回的任务 ID。

以下命令分别在具有正确 `MAAS_DATABASE_URL` 的私有运维环境执行。清单输出路径必须是私有目录下尚不存在的文件。

```sh
# 先在目标、再在源执行 freeze
python -m maas_platform.task_cutover freeze --model document.unlimited-ocr-2

# 源库冻结且排空后执行
python -m maas_platform.task_cutover export --model document.unlimited-ocr-2 \
  --manifest "$CUTOVER_MANIFEST"

# 核对本次源库生成的清单后，在目标库执行
python -m maas_platform.task_cutover activate --model document.unlimited-ocr-2 \
  --manifest "$CUTOVER_MANIFEST"
```

导出文件为 `0600`，仅含模型名、项目、键摘要与原任务 ID。保留源库身份、清单摘要和切换时点的私有记录。`activate` 在一笔事务内检查目标碰撞、保留键及开放目标模型。源或目标有未排空任务、未确认执行时命令拒绝。关闭或失败只影响该文档模型的新提交，库内已有工作继续按其原约束处理。

## 历史入口与调用方重试

原库冻结后，在旧文档 Nginx 配置的 `document_closed` 映射中采用以下规则，保留既有路径白名单、访问控制、上游和错误响应。

```nginx
map "$request_method:$uri" $document_closed {
    default 0;
    "~^POST:/maas/v1/(artifacts|tasks/[a-z0-9_]+/cancel)$" 1;
}
```

原入口的 `POST /maas/v1/tasks` 继续到达 MaaS，由原库在同一受理流程内返回旧键回执或拒绝新键。用 `nginx -t` 检查配置，加载后分别验证历史读取、旧键回执、新键、上传和取消。回退时先完成键交接与原库开放，再恢复原入口上传和取消。

调用方保存每次提交的发起入口、请求体和 `Idempotency-Key`。如果另一侧返回 `409 IDEMPOTENCY_OTHER_STORE`，以同一项目身份将原请求体和原键发回记录的原入口，取回原任务 ID，并在该入口查询任务、文件和用量。只有这个错误码使用此分支，普通 `409 IDEMPOTENCY_CONFLICT` 保留原有报错处理。

## 回退

交换两侧角色。先冻结统一入口上的文档新提交，排空切换后已受理的任务，导出统一库的文档键，在原库导入并开放。统一库保留切换期间产生的文档任务和回执，继续承接既有图片模型。两侧都保留支持 `013` 的版本和键保留记录，防止回退后旧重试重复执行。入口回退时保留两库的数据与查询位置，不用旧时点备份覆盖有新增写入的库。

## 演练证据

独立 PostgreSQL 两端通过真实 API、执行器、PDF 渲染及结果落盘完成正切和反向回退，上游推理使用固定模拟响应。另用 `pg_dump`、`pg_restore` 和独立文件副本证明可复原原任务、任务附件及收据，恢复出的文档冻结有效。测试覆盖同项目撞键、两方向重试、源文件无法由另一库直接引用、越权查询、文件过期、以及存在 `UNKNOWN` 时拒绝交接。

专项及相关回归 **114 通过、1 跳过**。复测使用三个彼此独立的可销毁 `_test` 库，分别设置 `MAAS_TEST_DATABASE_URL`、`MAAS_CUTOVER_SOURCE_TEST_DATABASE_URL`、`MAAS_CUTOVER_RESTORE_TEST_DATABASE_URL`，并设置 `MAAS_TEST_PG_BIN` 指向 PostgreSQL 工具目录。执行 `python -m pytest tests/maas/test_task_cutover_integration.py -q`，恢复目标库须为空。

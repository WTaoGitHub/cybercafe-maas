# 单张图片内嵌异步提交：实现与验证

日期：2026-11-02。状态：代码完成，本地和独立PostgreSQL/mock推理通过，**未部署现网、未进行真实GPU验收**。线上8副本配置未修改，无VM/worker/Docker引擎重启。

## 交付

POST /maas/v1/tasks新增input.image.data_url；仅PNG/JPEG严格base64 data URL，与artifact_id互斥。默认解码10MiB、20MP。任务路径内嵌JSON默认20MiB，已有artifact请求仍64KiB，其他非同步JSON路径限额保持。原始图片复用同步图片校验，无外部URL下载。

adapter input_schema/capabilities可描述两种形式；提交时保存图片并把任务input规范化成artifact引用，worker、TaskView、后续查询/取消/下载无需变更。仍要求Idempotency-Key，原请求指纹不包含随机生成的artifact ID；同键同请求复用200，新任务202，内容冲突409。

持现有文件生命周期锁，并在同一数据库事务/维护行锁下完成队列、文件配额检查及输入/任务登记。幂等查找在写文件前；原引用方式不额外持文件生命周期锁。无数据库迁移。提交失败或确认丢失不立即删除磁盘文件，现有孤儿GC按数据库引用兜底；保留现有上传/结果保存锁语义，未建设大文件流式上传。

## 测试证据

- 本地：68项通过，覆盖联合输入schema互斥、未知字段和参数、分块请求限额，以及已有同步OCR/连接器回归。
- 独立数据库API/mock推理广泛回归：78通过、1条件跳过（已有测试要求独立host数据库中断harness，本轮未提供；不是新功能未测）。
- 随后新增提交确认丢失和真实大图>64KiB两项，再运行全部内嵌集成用例：14通过，包含前轮12项重复，不能把两次通过数相加当成不同用例数。
- 同一key六并发只创建1任务和1输入文件，5次200+1次202；修改内容409。文件落库只含artifact引用，不保存内嵌base64。真实API→mock推理→成功唯一计量→结果下载，原引用路径回归通过。
- 格式、媒体声明不匹配、像素、字节、未知参数、权限、队列满、文件配额拒绝均无任务/文件残留。
- 文件写入/登记前失败无有效引用；提交确认丢失模拟中保留已提交任务/输入，再以原键请求返回200且不重复写入；孤儿GC验证通过。
- 大于64KiB的真实PNG内嵌提交、原字节下载、取消、幂等返回取消状态、capabilities联合schema通过；无内嵌来源的大JSON保持413。
- OpenAPI3.1、9路由及入口白名单一致性、JSON/YAML等价校验通过；文档标明新实现待部署。

隔离测试使用专用_test数据库及临时测试容器，GPU推理完全mock，未调用生产API或修改生产数据库。原始私有日志已保存到Mac忽略目录，未加入Git；隔离环境并发和硬件证据不代表生产性能。

## 使用形式（待部署）

```json
{
  "model": "ocr.default",
  "input": {"image": {"data_url": "data:image/png;base64,..."}},
  "parameters": {},
  "timeout_seconds": 120,
  "max_attempts": 1
}
```

请求头须带Authorization和Idempotency-Key。同次重试保持原key和body，不要改成新artifact引用或重新生成key。只承诺完全相同请求，不将不同data URL编码规范化为同一幂等内容。默认值语义保持原TaskCreate规则。

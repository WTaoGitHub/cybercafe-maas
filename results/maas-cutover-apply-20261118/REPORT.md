# 新 PC 测试环境统一任务库切换

2026-11-18 · MaaS 源码 `aeca549` · [Issue #62](https://github.com/WTaoGitHub/cybercafe-maas/issues/62)

新文档任务和 PP-OCRv4 任务在 `maas` 库共用 MaaS API 和一个执行器。原文档 API 与 `maas_document_m2` 保留历史查询和原键回执。旧文档执行器已停用，原文件卷仍按现有规则清理过期文件。统一执行器保持一个静态并发槽位。

统一目录保留 `ocr.default → maas-ocr`，新增 `document.unlimited-ocr-2 → unlimited-ocr-2-nfs`。文档运行依赖通过已有 PDFium Dockerfile 离线加入当前控制面镜像。API 和执行器的 Compose 配置追加 `compose-unified.json` 固定统一镜像，服务重建时沿用这组配置。现有控制面入口随 API 提供两种模型，实际下游容器通过同一个文档 Nginx 的新增私网监听提交统一任务，旧监听用于文档历史查询。

两侧原先使用同一个 GPUStack key，MaaS 内分别归属两个项目。统一入口保留原图片项目及凭据，并为其增加文档模型权限。切换时把旧文档库导出的 54 个历史键映射到统一入口的项目并进行事务内冲突检查。原任务、附件和收据继续由原项目和原库持有。

| 实测项 | 结果 |
| --- | --- |
| 下游容器使用原 API key 提交单页 PDF 和 PNG | 两个任务均一次成功，仅在统一库建任务，按一页和一张图片分别计量 |
| 统一 API 的 PP-OCRv4 同步接口 | 回环请求成功并产生一条一张图片的收据 |
| 旧任务查询、结果下载和用量 | 与切换前的结果字节和收据一致 |
| 旧任务原请求与原键重试 | 旧入口返回 `200`、原任务 ID 和 `Location`，统一入口返回 `409 IDEMPOTENCY_OTHER_STORE` |
| 历史入口写操作 | 新文档任务、上传和取消均返回 `503` |
| 执行与访问控制 | 一套执行器运行，两库均无 `UNKNOWN`，新入口拒绝无认证及白名单之外的请求 |

切换保留两库及文件卷，实际下游验证使用容器内的 curl。回退需要先冻结统一库的新文档受理并排空文档任务，导出这次切换后在统一库受理的键，映射回旧项目后导入旧库，再恢复旧库执行器和文档入口的写权限。[实测结果](VERIFICATION.json) · [切换与回退手册](../../deploy/maas/TASK-CUTOVER.md)

## 旧 GPUStack 部署退役

2026-11-18 删除使用 worker 本地权重的 `unlimited-ocr-2` 部署（模型 11）。GPUStack 实例记录与 worker 6 的推理容器均已移除。原权重仍在 worker 本地，同名 GPUStack 路由当前没有目标。

历史 MaaS 入口的模型授权检查已改用 `unlimited-ocr-2-nfs`。删除后以原请求和原键重试，历史入口返回 `200`、原任务 ID 和原收据。实际下游容器在统一入口提交一页 PDF，NFS 部署一次成功并生成一页收据。GPUStack 读回 NFS 部署为 1/1 Ready，PP-OCRv4 为 2/2 Ready。

## 隔离试验资源清理

2026-11-18 删除 8 个已交付的镜像中转包，保留发布记录。清理前确认文件没有容器挂载或打开句柄，清理前后均核对了 Registry 中的镜像清单和 62 条镜像层及配置引用。已移除仅有一条测试任务且无连接的 `maas_document_m2_test`、临时代理演练目录、旧 M2 构建目录和上传包。新 PC 所在文件系统的可用空间增加 **106.3 GiB**。Mac 上两个已停止的隔离 PostgreSQL 目录合计清理约 **100 MiB**。

清理后，旧文档库保有 54 条历史任务和 54 条收据，统一库保有 54 条旧键保留记录。实际下游容器用原键重试返回原任务和收据，并通过统一入口成功完成一页 PDF，PP-OCRv4 能力接口返回 `200`。

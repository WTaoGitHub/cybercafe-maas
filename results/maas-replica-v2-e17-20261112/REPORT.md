# R4 常驻 E17 路径集成与接管/恢复演练

2026-11-12 · [HTML](REPORT.html) · [核对数据](validation.json) · [Issue #39](https://github.com/WTaoGitHub/cybercafe-maas/issues/39)

已在实际 E17 采集/调节进程中验证 v2，而非上一轮每秒轮询的独立试点工具。**本轮集成演练通过，原 E17 已恢复原镜像和配置；尚未正式启用原业务的 v2 策略。** 原 OCR 目标保持 1，过程抽查及结束核对为 1/1，原 API、执行器、GPUStack Server、worker、VM 与 Docker 引擎未重启。

## 验证结果

| 场景 | 真实结果 |
| --- | --- |
| 实际双订阅 + E17 写库 + v2 Observe | workers / model-instances 订阅 connected，观测持续写入；计算可扩容但无接管时零写入 |
| Observe 显式接管目标 0 | CLI 返回 native_models_updated=false；仅保存接管基线 |
| Apply，上限 1 | 无新 worker 到达事件，自动 0→1；策略文件更新至确认约 12.34 秒 |
| 暂停后将策略上限提高到 2 | 仍为 1/1；状态 controller_paused，明确存在计算目标 2 的缺口但不写入 |
| 暂停状态下重启 E17 进程 | 接管内容哈希、代次、确认回执、目标及原生实例 ID 保持；重新订阅并持久化新会话 |
| 显式重新接管当前目标 1 | 暂停解除，实际主循环自动 1→2；没有重放前一次动作 |
| 人工将独立试点改成 0 | 检测 external_change；策略仍可到 2，但约 96.7 秒观察内没有自动补回 |
| 用错误目标 1 重新接管 | CLI 拒绝，接管状态未改变；正确采用 0 后退回 Observe 并暂停 |
| 实际 OCR / MaaS 异步 | 两次原生授权 OCR 返回 200，文字检查通过；原业务一项异步任务成功，唯一执行/用量/回执均为 1 |
| 恢复原 E17 | 同一原容器、原镜像、原配置及原策略恢复；采样新鲜、日报查询 200、UNKNOWN=0 |

自动写入只有两笔，均作用于独立试点部署：0→1、1→2。从候选容器日志、持久确认回执及原生目标独立核对，无待确认写入。人工归零单独记录，不当作自动缩容。模型上限与运行时写授权都仅针对试点；原业务部署不在候选写授权中。

第一次确认时延是“更新试点策略文件到持久确认”的本轮观测值，不是新节点注册时延，也不是模型可服务 SLA。候选运行真实 E17 的双订阅和 30 秒周期兜底，容量稳定期 2 秒、pressure=disabled；没有增加逐 worker SSH 采样。

## 发现并修复 E17 退出问题

未修复的 Python 采集进程没有在停止宽限期内退出，Docker 最终强制结束，演练记录退出码 137。暂停的接管状态和模型实例仍保留，证明持久保护生效，但这种停止方式会妨碍可靠清理。

已在 **e447154** 增加 E17 服务入口的 SIGTERM 处理：取消现有采集任务，等待其既有 finally 清理订阅、调节任务及数据库会话；重复 SIGTERM 不再次打断清理。非停止信号引起的取消和真正的采集异常继续向上抛出，不伪装成功。该处理不修改模型目标，不重试原生写入；发生取消时，既有持久写入日志仍按原流程保留。

| 演练 | 退出码 | 停止/重启至订阅及持久观测恢复合计 |
| --- | --- | --- |
| 未修复候选，暂停状态 | 137 | 15.62 秒 |
| 已修复候选，暂停状态 | 0 | 5.62 秒 |

两轮都确认目标仍为 1、原生实例 ID 不变、接管内容哈希未变、无未确认写入，并产生新的 E17 观测会话。修复候选最终停止并恢复原 E17 时也正常退出为 0。这里停止的是 E17 控制进程，不是 worker 或 VM。此次停止均在暂停且无 PendingWrite 时执行，不能据此宣称已验证真正写入在途时的网络结果不确定恢复。

本地去重回归 **114 通过、3 条件跳过**；跳过来自本机未配置的原生 SDK/独立测试库条件。新增测试实际向子进程发送两次 SIGTERM，核对退出码及子任务清理；还核对真实异常和外部取消仍能传播。原有 Starlette/AnyIO 弃用警告不影响结果。候选修复已实测，但当前恢复的原常驻镜像尚不包含该修复，随 R5 发布。

## 采样覆盖、日报与业务回归

恢复后，最近已封存日报查询返回 200，7 条记录、coverage 字段齐全，HTTP 内容与数据库载荷一致；API health 返回 200。E17 写库持续性和新会话均已核对。

演练窗口为 **1641 秒**，按现有同会话/最大间隔规则可确认覆盖 **1566 秒（95.43%）**，未覆盖 **75 秒**。窗口内观察到 6 个采样会话；会话边界及窗口尾部仍按未覆盖处理，没有补算为连续观测。该比例只针对演练窗口，不是完整日报的全天覆盖率，更不表示推理服务停机了 75 秒。

两次原生 OCR 使用仅允许试点模型、30 分钟有效期的临时 inference key。另用原有 MaaS 客户绑定验证原业务异步任务，数据库核对一次执行、一条成功用量和一条 OCR 收据，successful_images=1，UNKNOWN=0。没有将管理 key 替代 MaaS 客户 key；临时 key 已撤销，原客户 key、绑定和模型目录未变。

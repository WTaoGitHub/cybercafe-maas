# 增量副本规划验证

2026-11-24 发布候选 `d142604`。常驻 MaaS v2 按本轮空闲启动名额选择已经证明可放置的新增副本。候选受模型最小副本数、优先级、权重、模型上限、兼容卡和在途预算约束。超过规划时限时保留已证明的增量。原完整求解保留为独立的离线分析入口。 [REPLICA-INC-001](https://github.com/WTaoGitHub/cybercafe-maas/issues/71)

## 模拟验证

- 13 个模型各设上限 32，合计 416。以 26 个现有 Ready 副本开始，对 100、500、1000 台模拟 worker 回放集中上线、离线、恢复及全部离线。每批上限 4，有足够空间时生成 4 个新增建议。部分节点离线时重算仍可用的 GPU，全离线时停发新增并保留规则最小副本数。
- 用仅够两个副本的显存验证批次返回 2。用可控时钟在第一个副本证明完成后触发超时，保留已证明的一个副本。写侧从分页 API 读取到 1000 个 Ready worker，并正确忽略 11 条离线历史记录。
- 调节器及插件回归 **210 通过、2 跳过**。两个跳过项需要固定的 GPUStack v2.2.3 测试运行时。模拟验证覆盖 MaaS 的规划、快照和写入保护，真实千节点管理面容量按 E7 单独验收。

## 实机验收

三个现有模型和 10 张 Ready GPU。开始前 PP-OCRv4、OvisOCR3、Unlimited-OCR-2 分别有 5、2、1 个 Ready 副本。只读候选 31.51 毫秒取得快照并生成下一步 OvisOCR3 `2→3`，新增额度为 1。保存私有 Compose 回退文件到运维端，部署仅重建调节器所在的 E17 容器。第一次校验等待稳定状态超出窗口，已回退并保持暂停。再次切换后以新鲜的暂停快照核对授权、计划、原生副本和未确认日志，原有实例保持 Ready。

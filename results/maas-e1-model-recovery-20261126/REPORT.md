# 三模型故障恢复与新快照交接

2026-11-26，测试环境的 A 专用 PP 已退役。共享 PP、OvisOCR3 和 Unlimited-OCR-2 继续使用签名终止证明自动结清。控制端已打开 `MAAS_REQUIRE_MODEL_RECOVERY=1`。新上游模型继承相同准入条件。上线时须在引擎首次 GPU 操作前取得执行授权，按签名发布接入镜像摘要、入口、回执和见证路由。[接入规范](../../deploy/maas/MODEL-ONBOARDING.md)

## 实机结果

| 现场检查 | OvisOCR3 | Unlimited-OCR-2 |
|---|---:|---:|
| 非特权副本就绪 | 2/2 | 1/1 |
| 真实异步故障 | 2 笔 | 2 笔 |
| 原进程存在、无终止证明时保持 UNKNOWN | 2/2 | 2/2 |
| 原进程退出，验签后并发只释放一次 | 2/2 | 2/2 |
| 失败任务重跑／成功计量 | 0／0 | 0／0 |

每个模型的第一笔先以只读方式拿到签名终止证明，再启用自动结清。第二笔从派发前即开启自动结清。四笔都暂缓了原结束回执，等宿主机确认原进程仍在，再通过 GPUStack 替换对应推理副本。每笔都在结清后收到了迟到回执。另有三笔异步成功请求，其中一笔 Ovis 请求在原卡隔离期间取得另一张卡的授权，并在原任务结清前完成。

第二笔故障从进入 UNKNOWN 到结清，Ovis 为 65.17 秒，Unlimited 为 61.12 秒。这包含为确认原进程仍在而主动等待的时间。常规故障的 60 秒 P95 门槛仍待按同一口径批量验收。Ovis 和 Unlimited 的公开入口均为异步。现有一笔历史同步 UNKNOWN 仍保留。[实测与清理记录](acceptance.json)

## A 下线后的现场核查

先冻结 A 的新异步提交、停用专用凭据，实测 MaaS 返回 401。随后撤销 GPUStack 原生路由对该身份的授权，实测返回 403。按逻辑模型、派发路由和部署池核对，A 的排队及活动任务、同步未结清执行、异步未结清执行均为 0，随后才将期望副本调至 0。GPUStack 回读为 0/0，实例列表为空。MaaS 已移除 A 的模型目录项、凭据绑定和容量池，专用采样定时器已禁用，采样服务已停止。GPUStack 保留零副本的模型定义和无授权的路由定义。

## 三台新 worker 的验收

Tower 母版 `tower-e5-model-recovery-v5` 已回读并验签 `model-recovery-98adc70c1614`，33 个清单文件摘要一致。母版有四条见证路由，容器数为零，实例身份与本次启动的见证密钥均在克隆后生成。此次实机样本使用现有三台 worker 已登记的宿主凭据；按启动登记新凭据的首启流程已通过隔离测试。

1. 管理员从该母版制作平台快照，记录快照 ID，从快照启动三台独立测试 worker。核对每台的签名 revision、GPU UUID、此次启动的凭据、回执定时器和三个在用模型的实际副本。共享 PP 当前限定原三张 GPU，若 GPU UUID 改变，需更新共享 PP 的选卡范围。Ovis 和 Unlimited 没有旧卡绑定。
2. 全部 worker 离线时核对 GPU 新授权为零。控制端可以用原签名凭据复核已保存的终止证明；单凭失联或新 worker 上线，未拿到原执行终态证据的任务继续保持 UNKNOWN。
3. 容量恢复后，逐模型验证新请求、原任务只结清一次、健康卡授权和重试落点。时延验收从进入 UNKNOWN 到首次结清计时，将人为等待原进程存活的样本单列。平台快照、三个新实例的首启及常规故障 P95 尚待实测。

本地 MaaS 全量回归的一次运行有 25 项失败，其中 24 项在变更前的对照运行中同样失败，余下一项供给负载测试单独复跑通过。执行守卫、签名结清、文档及模型接入的针对性回归已通过。[E1 跟踪](https://github.com/WTaoGitHub/cybercafe-maas/issues/2)

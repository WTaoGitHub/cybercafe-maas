# E3-TUNE T0工具验收

2026-10-29。**T0-TOOLS完成，T0-BASELINE三轮真实OCR测量尚未开始。** 本轮完成工具、有界发压、运行保护及独立模拟验证，没有变更正式应用、模型、额度、路由或防火墙，没有重启VM、Docker引擎或worker，也没有恢复collector。

| 内容 | 结果 |
|---|---|
| 有界参数 | 支持1–16；覆盖6副本、6/8/12执行器与独立G/P/Q参数，非法值在操作前拒绝 |
| 持续补量 | 预上传、预填、水位补量、独立采样，下载/对账放在测量窗口之后；未知受理不重发 |
| 测量有效性 | 断粮/采样空窗作废，完成数取已提交ID边界差，尾部单列；不删除空闲片段或自动重开 |
| 选择与保护 | 按ID/模块/labels选择、依赖证据哈希、运行时身份/模型/参数fence、实际原值恢复前检查 |
| 发压引擎 | 有界原生/同步预备请求、独立到达时钟；忙/迟发/未发送如实记录 |
| 本地回归 | **90通过，0失败** |
| 独立PostgreSQL回归 | **63通过，0失败，1条件跳过**，使用模拟模型；临时测试容器限制2CPU/2GiB |
| 控制端只读实检 | 两worker、四running实例、GPU身份/原生指标、配置稳定性及独立测试库只读连接通过 |

独立数据库新增11个调优用例，覆盖6/8/12多进程领取、同步与异步共享全局/项目额度、同项目多key的原子队列额度、有效输入/TTL固定、未提交事务与完成边界，以及持续补量至结果下载。既有暂停、UNKNOWN、退出收尾、唯一计量、GC固定活动输入和恢复门槛回归同时通过。

唯一跳过的是`test_real_postgres_interruption`：需要专用host侧数据库停机实验入口。本轮没有启动该入口，也未停止数据库；它不属于T0准入/供给工具的验收要求，不能把此跳过算作数据库停机恢复通过。

当前正式配置经只读读取仍为R4/E4/G4/P4、Qg1000/Qp100、每副本2GiB、generation56、GPUStack v2.2.3。没有发布6/8/12配置，也没有得出新的OCR吞吐或最佳组合结论。

测试过程曾发现私有挂载目录权限、测试夹具默认重试数及手写计量夹具漏填quantity的问题；修正测试启动方式和夹具后重新验证。首次只读指标检查也发现系统Python缺httpx；在临时工具目录用已测版本锁创建隔离venv后通过，不向系统Python或正式应用装包。原始失败记录及完整运行时快照保留于Mac私有目录，未写入Git；最后清洁回归结果有独立校验摘要。

当前CLI默认dry-run，支持已经配置好的T0-BASELINE/T2纯异步单点，不会自动扩缩和回退。完整T1/T3/T4在线编排、混合/拒绝判定及候选选择、T6长时驱动仍在对应阶段集成，不把矩阵规划输出冒充已经执行。

**下一步**：先把完整模型配置、app.env和维护绑定备份到Mac，冻结40图预上传清单及profile，在现值下做三轮T0-BASELINE（每轮至少60秒且200个成功），核对持续供给、计量、资源及前后配置，再开始T1粗筛。供给证据是离散采样，只能表述为该分辨率内未观测到断粮，不能据此声称绝对连续供给或最大持续吞吐。

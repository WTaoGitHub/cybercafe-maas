# MaaS 文档任务代理切换演练

2026-11-18 · MaaS 修订 `aeca549` · [Issue #62](https://github.com/WTaoGitHub/cybercafe-maas/issues/62)

在新 PC 上，用正式文档代理的 Nginx 镜像和路径白名单启动两组临时代理，对接两个独立的测试库。由实际下游容器 `kc-e2e-aliyun-slave3-server` 内的 shell 和 curl 发送请求。文档任务调用 GPUStack 的 `unlimited-ocr-2-nfs`，图片任务调用 `maas-ocr`。样本为单页 PDF 和 PNG，使用限时、限模型凭据。

| 检查 | 实测结果 |
| --- | --- |
| 原文档入口进入历史模式 | 任务、用量和结果可读。原请求与原键返回 `200`、原任务 ID 和原 `Location`。新任务、新上传和取消均返回 `503`。 |
| 正切期间原请求误投统一入口 | 返回 `409 IDEMPOTENCY_OTHER_STORE`。容器内脚本识别该错误码，用原请求和原键回到原入口，返回 `200` 和原任务 ID。 |
| 回退期间原请求误投旧入口 | 同样返回 `409`。容器内脚本回到统一入口取得原任务 ID。两侧跨切换前后的历史结果字节和收据一致。 |
| 回退后的请求 | 原入口接受新文档。统一入口冻结新文档，仍可完成 PP-OCRv4 图片任务。 |
| 访问控制 | 无认证请求返回 `401`，未列入代理白名单的路径返回 `404`。 |
| 任务与计量 | 四个异步任务全部成功，每个只执行一次。收据记录三页文档和一张图片，共四条收据。两库无 `UNKNOWN` 或 `DISPATCHING` 残留。 |

首次启动因临时源码挂载根目录权限导致非 root API 进程无法就绪。确认目录权限并修复后，重新从空测试库完成演练。试验结束后已撤销试验凭据并清理下游临时文件、临时容器和数据卷。前后核对正式 API、执行器、代理、数据库和下游容器的 ID 与启动时间一致。

本次验收覆盖代理规则及容器内的重试分支。正式文档流量仍走原入口。生产库与文件备份、生产代理发布、下游业务调用方的重试逻辑和小批切流待验收。

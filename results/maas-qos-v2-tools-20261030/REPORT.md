# E3 v2测试工具适配验收

2026-10-30。状态：工具验证完成，真实OCR候选与容量复测尚未开始。MaaS业务源码、常驻镜像/配置、模型副本和额度均未改变；没有VM/GPUStack worker/Docker引擎重启，没有共享写入锁增强或新增常驻监控。复用独立测试数据库，未对正式数据库运行破坏性测试。

## 交付

| 工具能力 | 当前结果 |
|---|---|
| 显式新profile矩阵/实际应用image ID绑定 | 配置与证明记录矩阵、框架绑定哈希，拒绝跨profile、输入、矩阵或框架的证明；实际检查控制端容器image ID |
| 已核对新T0基线只读导入 | 绑定已有验证摘要，不发送任务、不补造新测量；不把旧profile改名解锁 |
| T2候选筛选 | 完整有效窗口中取5%带内最多两组较低资源候选，输出明确交接证明 |
| T3-MU | 每组候选独立3轮饱和测量，最低完整窗口成功完成率作为参考，不沿用旧最好数字 |
| v2队列判定 | 普通5秒/突发15秒/边缘及过载30秒，普通零拒绝；突发设最低受理量，不允许全部拒绝冒充通过 |
| 独立正常确认 | 预冻结45主点＋20个可能确认点；只对入围Q作第2、3轮正常验证，未执行点写明原因 |
| 无合格候选与故障分离 | 指标不合格记录QoS拒绝；全部已核对且无UNKNOWN时受控恢复原配置并标记REJECTED、退出2；故障或证据不足中断，不自动恢复/重放 |
| 完成时间 | 读取成功快照后再读取数据库时钟，记录首次提交可见时间的保守上界；0.5秒取成功ID，其他队列采样不变；不把updated_at或statement_timestamp当精确提交/客户端时间 |

策略、矩阵、输入、选择点、已有输出和任务命名空间须在参数变更前校验。旧v1驱动和旧自动续跑入口拒绝绑定v2的新矩阵，避免隐式回退；当前使用显式阶段，不自动启动HTTP/T5/T6。规则仍是内部实验目标，不是对外SLA。

## 验证与失败保留

- 本地相关回归74通过；独立环境最后一轮40通过、无失败/错误/跳过。集合有重叠，不相加冒充独立测试数。
- 独立环境包含真实API、PostgreSQL、mock任务执行/结果/计量，以及完整arrival点测量代码；GPUStack/硬件/运行探针在该点测试中为stub。依赖、矩阵、应用镜像拒绝和策略判定由独立单元用例覆盖，不等于在真实GPU环境完成容量验收。
- 第一轮38/39通过：mock快照generation错误设为1、实际测试库为0，保护正确阻止继续，改为读取实际值。第二轮39/40通过：新增T2筛选的导入测试暴露隐式模块路径依赖，改用独立的私有日志原子写函数。第三轮40/40通过；三轮JUnit/日志及最终原始点记录已备份Mac私有目录，原失败不覆盖。
- 201个隔离源文件逐项SHA256核对；最终代码及新矩阵/策略与验证包哈希一致。新增真实DB用例还验证了跨命名空间隔离、只读观察连接、旧任务命名空间拒绝及deadline证据校验。

见[机器可读验证数据](validation.json)。完成观测是保守上界；若采样不能证明原deadline内成功可见，宁可中断为证据不足，不用事务内更新时间伪造通过。时钟倒退也拒绝；没有精确COMMIT时刻或断电持久性/SLA证明。

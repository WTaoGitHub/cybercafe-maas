# 两种终态证据的联合实机验收

2026-11-26，测试环境三台 worker 运行 A 专用 PP、共享 PP、OvisOCR3 和 Unlimited-OCR-2。A 和共享 PP 均开启签名终止证明自动结清。三个模型的常驻 worker 补报定时器都已启用。

## 同一笔任务收到两种证据

用 A 专用项目提交两笔真实异步任务，重试预算各为 3 次。按测试任务的幂等键，暂缓 MaaS 提交 GPU 结束回执。守卫在实际推理结束后留下原签名回执。客户任务失败，后台活动进入 `UNKNOWN`。此时逐笔核对原 GPU 授权、进程绑定、结束时间为空，以及该项目仍占用一个并发。随后终止原推理容器，宿主机以 MaaS 的有效随机挑战核查原容器、进程和 GPU，生成终止证明。验收在测试 worker 暂存这份真实报告，并控制两份证据的投递顺序。

| 控制端先收到 | 第一次结清 | 第二份证据及两次重投之后 | 并发占用变化 |
|---|---|---|---|
| 原进程签名结束回执 | `COMPLETED` | `COMPLETED` | 1 → 0，后续保持 0 |
| 宿主机签名终止证明 | `RESOLVED` | `RESOLVED` | 1 → 0，后续保持 0 |

两笔都在投递证据前观察到 `UNKNOWN`。本轮以真实 worker 补报服务投递两次同一原签名回执，为控制先后顺序手动触发该常驻服务。两份证据都到齐后，GPU 结束时间已登记，宿主机终止签名与原执行身份匹配。重复的宿主机报告均返回 409，重复的执行回执均得到确认。再次读取时，账本状态、GPU 结束时间和更新时间保持原值。数据库逐笔捕获到一次离开 `UNKNOWN` 的状态变更。客户查询两笔均为 `FAILED`、一次尝试、无结果及成功计量。

独立 PostgreSQL 回归另覆盖同步、异步两条路径。两个发送方同时提交原回执和当前挑战的宿主机报告，随后再投递两份证据，检查额度、状态和时间戳。测试命令为 `python -m pytest -q tests/maas/test_runtime_recovery.py -k delivered_together`。数据库前置条件见[部署手册](../../deploy/maas/INFERENCE-QUARANTINE.md)。

## 正常回传时的签名结清时延

另在 worker 34 的 A 路由独立注入 20 次进程退出，同步、异步各 10 次。每次确认原进程获得真实 GPU 授权后终止该容器，见证服务按常驻配置自动回传。待 A 和共享 PP 的副本都重新就绪，再开始下一次。同步原请求用正式 MaaS 同步处理程序及 Higress，异步原请求经 MaaS HTTP 任务入口。每笔都观察到没有终止证据的 `UNKNOWN`，随后按原身份、随机挑战和签名核验 `RESOLVED`。同步客户收到 503，异步客户查询为 `FAILED` 且仅执行一次；全批成功计量为零。

从账本首次进入 `UNKNOWN` 到提交 `RESOLVED`，同步 P95 为 **35.13 秒**，异步 P95 为 **35.01 秒**。以最近秩计算，每组 10 次的 P95 即该组最大值。可运行 `python -m scripts.maas.runtime.summarize_runtime_recovery results/maas-e1-joint-unknown-20261126/samples.jsonl` 复算。[20 笔样本](samples.jsonl)

## 三模型异步结果和计量

| 实际模型与落点 | 实际输入 | 客户可见结果 |
|---|---|---|
| 共享 PP，worker 32 | 图片 | 成功，一次尝试 |

| Unlimited-OCR-2，worker 31 | 单页 PDF 制品 | 成功，一次尝试 |

Ovis 的内联图片预检和 Unlimited 的多尝试预检各收到一次 HTTP 422，均在创建任务前结束。表中三笔均使用对应模型支持的输入，Unlimited 按接口要求只允许一次尝试。三个结果文件均返回 HTTP 200，内容与任务详情一致，并识别出测试文本。三笔均可对应到实际 GPU 授权及完成回执。每笔有一条任务成功事件和一条 OCR 用量记录。[验收数据](acceptance.json)

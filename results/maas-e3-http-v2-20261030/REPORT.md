# T4 HTTP接入：首轮包络和连续恢复

2026-10-30。隔离控制面17个窗口、真实OCR首次7个短突发点，以及额外2点同配置连续恢复复核完成。主流程约19分钟；补测单独保存。原配置最终恢复、监控正常。结果是已测请求/速率包络，**没有证明最大并发或生产接入上限**。

## A：隔离控制面，保留真实TLS/鉴权/API/数据库

API、发生器、16个受控mock消费者共同限4CPU/4GiB；独立TLS代理限1CPU/256MiB。专用测试数据库、文件目录、project，G/P=12、Qg/Qp=100。仅OCR执行被mock替代，鉴权仍访问真实GPUStack，不是GPU业务吞吐。HTTP/1.1、持久客户端、传输重试为0，仅服务器回环私有TLS；不是互联网或HTTP/2压力结果。

数据库与正式DSN不同且名称以_test结尾，重置前已备份Mac，测试后数据库与文件证据亦备份。首次备份gzip封装校验失败，在实验启动前重制并两端校验，未使用无效备份。

### 恢复连续性补证与工具修复

复核发现旧驱动在独立拒绝/恢复段之间先恢复、再应用模型/执行器配置，因此其恢复段只能证明重新配置后可用，**不用于证明同配置自然恢复**。保留原结果，补充工具193a398（相关24项测试通过），未来HTTP驱动自动使用连续恢复路径。

新独立复核：同一R10/E12/G12/P12/Q25配置提交100次压力请求，38次受理、62次拒绝；受理任务全部排空且下载核对后，再提交3个新请求，全部成功。两段间generation=324、模型实例、应用容器、完整运行快照哈希一致，没有中途恢复或重配，只有两段均完成后才恢复原配置。新复核41个受理全部成功、唯一执行/计量，62个拒绝无任务；T5前置应引用这一**连续恢复证明**，不能引用旧有干预的恢复段。

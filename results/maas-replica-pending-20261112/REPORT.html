2026-11-12 · 实现、隔离实测及单部署受控启用通过 · 代码 125298e · Issue #39

现在的行为

调节器只管理 replicas。确认资源不足的 Pending 连续有效观察满 180 秒后，把指定数收敛到 max(最新 Ready 数, 规则非零最小值)。逐次 -1、逐笔确认；同轮不用反复等 3 分钟。达到目标后保持，自身删除 Pending 不会导致立即扩回；真实容量、Ready、配置、策略或外部目标改变后重新规划。

原生镜像、参数、环境及资源声明保持最新值，不回滚、不作为暂停信号；容量规划读取当前原生显存声明。全局暂停、部署授权及未知写入保护继续优先。v2 最小副本和自动缩容下限不能为 0。下载、初始化、原因不明的 Pending 不能取得资源不足缩容权限。

遇到的问题与处理

数据库首次备份误用默认 Unix socket，按实际 TCP 配置修正后成功。入口检查首次误用了旧 HTTP 端口，核对实际私有 TLS 后通过，没有新增监听。

资源恢复首次只等待 30 秒，未等到原生已 Pending 实例重新调度，原超时和证据保留。两次有界只读检查后已看到原请求自然进入 Ready，没有重发、强制重调度或重启。后续使用 240 秒有限观测，记录到约 86.51 秒恢复 3/3。原生已 Pending 实例的再调度等待仍需优化，不能把本轮通过解释为“资源释放后立即全部就绪”。继续在 Issue #39 追踪。

限制与证据

允许删除多余 Pending 的能力绑定 GPUStack v2.2.3 已核验的 controllers/scorers 源码、评分配置、SPREAD 和无分配/无 claim Pending。证明仅在部署时核验本机容器，不是每节点 SSH collector。原生升级、评分设置或镜像改变后必须重新生成并验证；缺少证明时保留原健康保护。原生 API 没有 CAS，仍不能承诺外部持续并发变更零中断；意外丢失受保护实例或写入结果未知时保留日志并停写。

本轮没有重启任何 VM、worker 或 Docker 引擎，没有恢复自建 collector。没有在真实环境故意制造 UNKNOWN 或中断原生写入，没有完成冷缓存争抢及几百/千节点容量验证；普通镜像/资源声明热改的组合实测也未在本轮覆盖。CPU/RAM 联合求解、按模型暂停、已 Pending 再调度加速仍为后续范围，不能把旧 R4 全部余项或广泛生产发布门槛改判通过。

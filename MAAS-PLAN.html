网吧闲置 GPU MaaS
目标、解决方案与实施计划

利用网吧空闲时段的 NVIDIA GPU，通过 GPUStack 统一部署和路由模型服务，优先提供普通中英文 OCR 文字提取。当前阶段验证识别质量、多节点吞吐和运行成本，为后续商业服务及更多模型类型提供依据。

一、目标与范围

  • 长期目标：把分散的闲置显卡组织为可运营的推理资源池，向客户提供模型 API，提升设备利用率并探索盈利。
  • 近期目标：以两台服务器完成 GPU OCR 小规模验证，确定可用的模型、接口、部署方式、容量和成本边界。
  • 首期业务：普通中英文图片文字提取，返回文字、位置和置信度；暂不以复杂文档理解、表格结构还原为主。
  • 后续业务：text-to-image、text-to-video 等模型服务，待 OCR 链路和运营能力成熟后再扩展。

二、解决方案

本地 Mac：管理、开发、测试 │ SSH 隧道（本地无需对外提供入站访问） ▼ XZ-31-001：GPUStack 控制端 / 统一 API + GPU worker │ 内网调度与请求路由 ├── 001：OCR 实例 → RTX 4080 SUPER 16GB └── XZ-31-002：GPU worker → OCR 实例 → RTX 4080 SUPER 16GB 结果：暂由执行 worker 保留；持久任务与统一结果管理待建设

GPUStack 负责节点、后端、模型副本的管理以及统一入口路由。自定义 OCR 适配层使用 RapidOCR 和 ONNX Runtime GPU 执行识别，通过 OpenAI 兼容的 chat 接口接入 GPUStack 与 Playground；此处协议兼容不表示使用大语言模型，也不产生可计费的真实 token。

001 同时承担控制端和 worker，当前验证表明两种角色可以共存。它是现阶段的控制单点，必须保持 Ubuntu 在线。本地通过 SSH 隧道访问管理/API，当前没有直接开放公网商业入口。

长期设想为 Windows 服务网吧用户、Ubuntu 提供 MaaS。双系统启动属于节点可用性切换，不能实现同时使用；切换、任务排空及磁盘持久性仍需实测。此阶段没有计费软件，不引入 MQTT。后续若需要自动调度，可增加节点状态上报和上线/下线控制。

四、已经取得的证据

多节点与多副本能提高吞吐

早期合成英文样本上，GPUStack 单副本约 7.38 张/秒，双副本约 11.90 张/秒。后续真实混合图片测试中，相同已摆正模式、并发 8 下，两卡总副本从 2 增至 4，吞吐从 9.80 增至 15.11 张/秒，约为 1.54 倍。不同阶段输入与配置不同，不能直接横向比较。

质量需要按场景和方向选择策略

旧 v4 方向分类器会误旋转部分正常文字。0.3 方向保护保留原方向识别结果，仅在倒置候选的识别分数明显改善时采用。完整 160 张评估集的空间分组 CER 为英文 7.71%、街景 18.80%；v6 small 文档候选的英文 CER 为 5.52%。这些是特定公开数据和评分规则下的诊断指标，不能用 1−CER 直接对外承诺准确率。

方向保护主要覆盖 180° 风险，当前线上未增加 90°/270° 自动识别。实验接口的显式纠正角度来自调用方，并不属于自动方向预测。线上默认仍是 v4 方向保护，v6 为候选。

已知可靠性和运维边界

  • 历史停止 002 的实验中，60 次采样有 19 次 503，最后失败约在采样开始后 32 秒；GPUStack 本身尚不能保证任务无损切换。
  • 单实例推理锁会使并发请求排队；独立副本有助于利用 GPU 余量，但显存调度申报并非硬隔离。
  • 当前镜像依赖节点预加载；新增节点前需准备统一可访问的镜像仓库。
  • 识别完成后才发送 SSE 文本；Playground 可用不等于逐字实时 OCR。
  • 尚未验证连续 8 小时负载、Windows/Ubuntu 切换、商业订单或完整单位利润。

五、下一步：按业务验收收敛

  1. 明确客户输入和验收线：收集有代表性的实际图片，约定清晰度、方向、图片大小、文字类型、可接受错误和 P95 延迟。确认公开数据授权；RCTW-17 的商业使用条件仍需核实。
  2. 确定产品默认策略：正常摆正输入优先评估 upright；存在倒置风险采用 guarded；英文文档质量优先评估 v6 small。保持独立评估集，避免用校准结果代替验收。
  3. 收敛专用镜像与容量：使用专用单模型容器，以真实输入复测每卡 1/2 副本和并发，记录显存峰值、P50/P95、失败率及吞吐；不直接照搬临时双模型实验容量。
  4. 验证完整闲置时段：开展至少覆盖计划工作窗口的耐久运行，补测节点断连、恢复、任务排空、双系统切换与持久存储；001 控制端保持在线。
  5. 补齐服务能力：增加持久任务队列、超时重试、幂等任务 ID、结果查询与过期清理；再配置外部网关、鉴权、限流、配额、按图片/任务统计和监控告警。
  6. 完成经营核算：测插座整机功耗与实际闲置时长，计入网络、折旧、维护、失败重试及客户利用率，再用真实付费试单确定价格和毛利。
  7. 扩大资源池：先验证更多 worker 的稳定加入、退出与镜像分发，再逐步增加绘图、视频服务。

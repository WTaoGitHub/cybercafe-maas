# 调节器配置与资源声明热改实测

2026-11-13 · 工具已实现，真实执行待验收 · [Issue #39](https://github.com/WTaoGitHub/cybercafe-maas/issues/39)

验证调节器只修改 replicas、始终采用最新配置和资源声明，不以普通配置变化隐式暂停。使用新建的独立试点部署及专属注册引擎，不复用上轮故意保留未知 journal 的对象。正式模型、旧试点及正式引擎配置均作为受保护对象，前后核对配置/Ready/实例 ID。

## 原生配置与试点

当前使用注册引擎，镜像和启动命令通过试点专属 `backend_version` 切换测试。两版本使用同一仓库和 SHA256 内容摘要，只改变镜像引用；B 对已验证的 `--port` / `--model` 参数调整顺序，不加入未知启动参数，模型 env 增加无业务副作用的标记。新实例的原生日志须出现 B 镜像引用、参数顺序及环境标记，不能只看配置保存成功。

这验证了注册引擎方式的配置接入，不声称升级不同模型权重/镜像内容或任意启动参数均已验证。GPUStack v2.2.3 对非字面 `custom` 后端的模型级 image_name/run_command 覆写存在原生清理逻辑；本轮使用当前注册引擎原生支持的版本配置，不更改正式共享引擎来绕过它。

资源测试将试点限制到一张已就绪 GPU 的既有 worker-name 标签，不改节点标签、地址或防火墙，不重启 VM/worker/Docker。使用3.5GiB（既有验证预算）和8GiB两档，不通过降低到未验证的小显存预算挤入更多实例。

## 六项验收

| 场景 | 预期 |
| --- | --- |
| config_change | 在 Observe 基线后外部切 B 镜像/命令版本、env；Apply 自动扩容采用最新配置，无需再次 adopt。运行中普通描述变更不隐式暂停、不改回 |
| old_small_new_large | 旧3.5GiB实例保留实际申报，改新声明8GiB；单卡最大策略4但按真实剩余只增加一个8GiB实例。不得把旧实例重新定价8GiB缩掉 |
| old_large_new_small | 旧8GiB实例继续扣8GiB，改新声明3.5GiB；按真实剩余只增加一个3.5GiB实例，不能因新声明较小就多算空闲 |
| invalid_claim | 目标0时写非法声明；Apply 快照无效并显示 resource_claim_invalid，至少观察5秒零写入且非人工暂停；修正后无需 adopt/重启自动恢复 |
| missing_claim | 同上，缺失声明显示 resource_claim_missing，不回退旧策略提示值；修正后自动恢复 |
| paused_config | 全局暂停后改 B/8GiB 并明确运维归零，保持无新增调节；恢复后按最新B/8GiB重新启动；最大值4仍受单卡真实容量限制 |

混合占用必须现场计算 `1+floor((卡容量-保留-其他模型占用-旧实例占用)/新申报)`，并确认结果与将所有旧实例按新规格重算不同，防止策略上限掩盖算错。记录真实计算申报、旧实例ID、同卡落点、每笔已发送请求及最新配置。未分配/未知/混合不完整状态不能当作空闲资源。

## 工具与安全边界

`maas_platform/replica_hot_trial.py` 提供固定摘要镜像引用、已知命令参数变体及单部署±1发送边界记录器，拒绝配置改写、旧请求、越权对象、归零或超4的自动动作。`scripts/maas/replica_hot_live.py` 使用生产订阅/分页/对账/写入代码，临时容器设置 `PYTHONPATH=/app`，独立状态与实际子进程，E17观测持久化sink隔离，正式SQL/锁不变。

每案例结束后暂停并自然停止试点控制进程、检查journal为空，再明确运维归零和恢复试点基线。原始 journal 不能清空；失败时停写/保留现场，不盲目回退模型参数。异常最多两次有界诊断，仍不可继续立即停止，不改门槛、不重发不确定请求。每feature适当验证后提交并push，原始凭据/日志/地址仅私有保存，备份优先复制Mac核对SHA。

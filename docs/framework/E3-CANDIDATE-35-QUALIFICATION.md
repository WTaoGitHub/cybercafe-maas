# 3.5GiB新候选资源资格与容量校准

目的：为R8/E8/G8/P8/Q25/M3.5GiB取得独立、匹配的资源及容量证据，不沿用旧2GiB或R10/R12参数证明。

1. 核对旧实例画像、原生放置记录的摘要，以及模型、worker/GPU身份、业务镜像和固定配置；备份Mac。旧T5文件仅作输入内容/文字参考来源，不授权新claim。
2. 临时启动修复后的worker本地进程采样，每节点一条SSH长连接，最长1200秒；保留启动、负载、静置、回收全程。没有常驻collector或推理SSH门禁。
3. 持有全局排空和维护代次，0→8重建本模型推理容器，设置3.5GiB，核对8个原生计算申报及4+4放置。镜像/权重缓存热；不重启VM、worker或Docker引擎。再配置E8/G8/P8/Q25。
4. 第一窗口：同一50图80/20混合300秒饱和补量、至少200成功任务，全量核对后静置60秒。原资源保护不变，末分钟两个30秒高水位增长≤256MiB。未通过不测更后面的窗口。
5. 普通40图3轮60秒；混合50图3轮60秒，全部持续补量、每轮至少200成功任务、独立任务命名空间并核对全部结果。普通与混合各取三轮最低吞吐作保守μ；不拼接、不能交叉借用。
6. 全部通过才按精确当前快照恢复原claim、副本及执行器/队列参数。异常只停止新负载，保留证据，不自动重放/修复UNKNOWN或盲目恢复；核对后另行受控处理。

入口`python scripts/maas/runtime/qualify_candidate.py --config <私有配置> --execute`，默认dry-run。必须显式scope与Mac备份收据；每份实例画像/原生放置/来源快照按SHA256绑定。执行前检查当前精确快照、空闲无UNKNOWN、输入有效期覆盖1小时；项目/全局各预留512MiB预测输出，保留10%配额及磁盘余量，不删除有效输入、续期或增加配额。

既有T6工具已使用单独混合资格吞吐生成混合负载到达率。本轮再为两种输入分别做三轮校准，不将该机制误称为新修复。

本轮产出`CANDIDATE-QUALIFICATION-35`记录，不能自动冒充旧T3/T5/T6格式证明；后续队列/延迟驱动须显式接纳同组合、同输入的匹配新证明。普通/混合60秒μ不是最终五分钟确认或两小时验收。进程显存仍是采样高水位、RSS/HWM是辅助值，不证明瞬时绝对峰值；工具收尾修复须真实核对，不以本地回归代替。

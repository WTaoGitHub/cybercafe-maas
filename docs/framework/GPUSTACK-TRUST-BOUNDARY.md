# 设计重评：GPUStack作为推理运行状态权威

2026-10-22。背景：用户明确希望透明复用GPUStack，相信其声明的服务可用性；模型实例健康、资源采集与路由故障应由GPUStack负责。本轮为设计结论，**尚未修改代码/服务器/配置，当前正式预检仍存在**。

## 结论与原方案问题

取消“每次推理必须持有依赖约5秒SSH Docker核验的30秒新鲜证明”这一产品方向。该规则是本项目针对两节点固定部署增加的严格验证策略，不是GPUStack要求。它把管理清单采集故障转化为业务不可用，本次SSH限流正暴露了这种额外依赖；也不适合动态云网吧和大规模资源池。

运行期使用GPUStack提供的已授权模型入口，信任其worker/实例健康判断、调度、路由与内部重试策略；不在MaaS再建立一套全worker健康仲裁。无须以新增独立SSH通道作为消除推理门禁问题的主要修复。公网运维SSH稳定性仍可独立治理。

## 职责划分

| 事项 | GPUStack职责/数据权威 | MaaS职责 |
|---|---|---|
| worker心跳、GPU资源、模型实例状态 | 优先复用原生能力 | 展示/告警可消费已有状态，不重复SSH核对再裁决模型可用 |
| 推理路由、实例选择、内部尝试 | 信任GPUStack服务入口 | 向受信任配置的逻辑模型路由发送，不直连worker绕过 |
| 已批准模型与revision | GPUStack承载部署 | 保留本地目录/版本绑定、变更审批及发布验收，不要求逐请求实时镜像核验 |
| 客户权限、project与存储/队列配额 | 原生模型权限继续校验 | 保留本地登记、资源授权、共享准入与配额 |
| 超时/断连及业务任务 | 原生服务执行与状态 | 保存实际请求状态，处理结果/错误，未知结束不盲目重放，唯一成功计量 |
| 维护关机前实际进程终止 | 原生控制能力按已验证行为复用 | 管理活动排空/维护窗口；安全停机证据不同于正常服务可用，不因本决策删除 |

信任GPUStack的服务抽象，不代表承诺每次网络调用成功；调用失败仍需正常返回和记录。无需在每次推理前再向其控制面发一个新的健康判定请求，避免建立第二条实时可用性依赖。

## 保留与移出热路径

- 保留：鉴权/模型授权、输入校验、静态逻辑模型/revision绑定、队列/并发/存储额度、全局维护、请求发送意图、超时/UNKNOWN、输出校验及计量。
- 移出热路径：SSH Docker镜像清单、必须全两worker健康/固定分布的collector证明、30秒preflight新鲜度、实时网关策略指纹检查。
- 改为发布/变更控制：镜像内容/部署配置核验、模型版本登记、网关策略审查；按需要低频审计，审计通道故障只告警，不独立把正常推理封禁。经过确认的越权/错误配置属于独立安全事件，需人工处置，不等同于采集失败。
- collector不再是客户推理的必需在线组件；不立即停止正式collector，需等调用方/配置/监控依赖完成迁移后再降频或退役。
- 新承诺是信任批准的GPUStack部署与管理员变更流程，不再承诺每次推理前通过SSH独立证明运行镜像内容。不能一面移除校验、一面仍宣传同等实时完整性保证。

## 建议的P4修复实施清单

1. 修改OCR异步适配器与SyncIngress：去除实时preflight读取，保留受信任目录/静态版本绑定与原有授权和发送前活动账本。
2. 调整目录校验/启动配置，不再强制依赖consumer挂载与动态证明文件；旧字段/旧部署的迁移行为明确，不提供容易误配的静默安全开关。
3. 维护恢复保留实际业务探针及generation/UNKNOWN检查，移除“必须先等collector健康”的前置；恢复不伪造远端停止证据。
4. 独立监控将collector从影响业务健康的关键依赖移除或降为审计告警；继续监测API/DB/执行器、任务积压、上游请求失败与必要运行状态。
5. 测试证明：collector/SSH不可用但GPUStack服务正常时，同步/异步仍可完成；GPUStack实际不可用时，按请求结果正确失败或UNKNOWN；暂停、撤销key、配额、旧attempt与唯一计量仍有效。
6. 更新预检、运行手册及对外能力说明，审核迁移/回退，受控发布。原8小时失败证据保留；新基线使用新run ID重新完整验收，不自动续跑原测试。

本轮不执行上述发布。P4修复/验收仍先完成；E5之后立即启动，侧重复用GPUStack登记/心跳/资源上报，仅补真实云网吧设备身份与还原/克隆缺口，不预设另建完整agent平台。

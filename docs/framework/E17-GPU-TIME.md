# E17 GPU 每日与每月在线时长

## 需求与实施计划

1. 使用 GPUStack v2.2.3 的分页 worker 列表读取状态和 GPU UUID。按 UUID 汇总同一张卡在不同克隆上的记录。worker 名可以携带 UUID 方便核对，统计以控制面上报的 UUID 为准。
2. 运维通过定时任务采样，复用 MaaS PostgreSQL，使用 E17 专用 schema。建议每分钟采样一次，连续有效样本的最大间隔为 120 秒。部署前验证 UUID 跨克隆稳定性及列表权限。
3. 按北京时间自然日查询在线、非 ready 和未知秒数。前一有效样本代表到下一有效样本前的区间；采样失败、过长间隔、卡未上报或 UUID 冲突的区间归为未知。验证旧 worker 记录残留对统计的影响。
4. 增加北京时间自然月查询，将每日时长按 GPU UUID 累加。用固定时间戳验证跨日和月末切分。
5. 在隔离测试库完成实机试采，验收后再启用定时采样并开始积累历史。

范围以 GPU 在线时长为限。模型部署时长已移出 E17，下一版采样只读 worker 列表，查询也移除模型时长字段。

## 当前实现与验证状态

第一阶段已实现 PostgreSQL `e17` schema、worker 列表采样、日报和月报 CLI，以及默认关闭的 Compose 采集服务。隔离 PostgreSQL 回归通过。001 只读探测使用现有推理凭据返回 HTTP 403，第二阶段改用有列表权限的运维凭据完成实机试采。网页、JSON 查询和正式启用待后续阶段。

CLI 读取 `MAAS_DATABASE_URL`。采样另需 `MAAS_GPUSTACK_URL` 和 `E17_GPUSTACK_KEY_FILE`。数据库须先应用 MaaS 迁移。

```bash
python3 -m maas_platform.gpu_time report 2026-11-04
python3 -m maas_platform.gpu_time report 2026-11
```

报告列出截至统计期末已观测到的 UUID，当天统计截至查询时间。最后一个样本之后的区间在下一次有效采样前计为未知。

## 2026-11-04 阶段性决议

- **统计口径**。按控制面上报的 GPU UUID 汇总北京时间自然日与自然月的在线、非 ready 和未知时长。在线指 GPU 被上报且 worker 为 ready。当日和当月截至查询时刻。模型部署时长、推理忙时和利用率移出 E17。
- **采样与归属**。只读取 GPUStack worker 列表。建议每 60 秒采样一次，两个相邻样本均有效且间隔不超过 120 秒时，用前一样本估算该段状态。采样失败、超长间隔、未上报或无法判定归属计为未知。同一 UUID 唯一 ready 的记录可在实机确认旧记录已退出 ready 后接续计时，多条同时 ready 计为未知。worker 改名无需作为前置条件。
- **查询入口**。保留 CLI，在 MaaS 内置只读网页和 JSON 查询。网页支持日/月选择、GPU UUID 筛选，展示三类时长与最近成功采样时间。三种入口共用同一计算口径，月报按日累计。
- **部署与操作**。E17 作为 MaaS 内置运维模块，复用现有 API 进程、网关入口、鉴权机制及 PostgreSQL。网页和 JSON 查询路由纳入运维权限范围，验收须覆盖普通调用凭据无法访问。数据放在 E17 专用 schema，通过 MaaS 的迁移机制建表。定时采样由 MaaS 部署编排管理，只有采样进程持有 GPUStack 列表凭据。采样独立于推理请求，采集或查询异常按运维功能处理。
- **前置条件与验收**。先用运维凭据在隔离测试库确认 worker 列表权限，连续试采并对照 GPUStack 页面。用独立克隆验证同卡跨克隆 UUID 稳定性及旧记录残留。用固定时间戳覆盖跨日、跨月、采集断档和冲突，核对三类时长之和、月报与逐日汇总。用同一测试库对比 CLI、JSON 和网页，检查筛选、空数据和采集异常提示。
- **交付顺序**。收敛 worker 采样并补齐月报，完成隔离测试库实机试采，再交付只读网页与 JSON 查询，最后在 001 启用定时采样。网页可先用测试库开发验证。本决议记录后续实施范围，线上历史从正式采样开始积累。

SQLite 首版已由 PostgreSQL CLI 接替，网页和 JSON 查询将复用其统计逻辑。实机验收需经现有 MaaS 入口核对页面、JSON、运维鉴权和采样断档。

## 2026-11-04 采集容器决议

查询网页和 JSON 接口由现有 MaaS API 容器提供。采集使用同一 MaaS 镜像，以独立命令启动 Compose 服务 `e17-sampler`，复用现有 PostgreSQL 的 `e17` schema。采集容器仅发起出站请求，GPUStack 列表凭据只注入该容器。独立启停、日志及资源限制由 Compose 管理，历史报表在停采期间仍可查询。

- 通过 Compose profile 默认关闭采集。数据库迁移和试采通过后，执行 `docker compose --profile e17 up -d e17-sampler`。启动立即采样，周期默认 60 秒，单轮超时 30 秒，同进程内采样串行。
- 使用 `docker compose stop e17-sampler` 停采。收到停止信号后停止调度下一轮，给当前轮次留出有限收尾时间。恢复时执行同一启动命令。
- 首版部署单实例，使用 PostgreSQL 锁防止重复启动造成并行采样。每次启动创建新采样会话，跨会话间隔计为未知；同会话最大有效间隔仍为 120 秒。
- 验收覆盖重复实例、停止和恢复、短停采间隔、采集失败，以及停采期间网页和 JSON 历史查询。

首次实机试采使用隔离数据库。正式部署时，在 Compose 私有环境中配置 `E17_GPUSTACK_KEY_PATH` 为仅运维及容器 UID 10001 可读的凭据文件绝对路径，并确保所选 MaaS 镜像包含迁移 007 和采样命令。同 UUID 出现唯一 ready 记录时计为在线，多条同时 ready 或多条均非 ready 时计为未知。


## 第二阶段实机试采

在 001 使用授权运维凭据读取 GPUStack worker 列表，并写入隔离 PostgreSQL。读取到 6 条 worker 记录、4 个 GPU UUID。匿名状态组合为两张单记录卡（ready、not_ready 各一张）、一张 ready 与 not_ready 并存、一张有两条 not_ready。修正后连续三轮试采覆盖 10 秒，两张卡在线、一张非 ready、一张未知，日报累计在线 20 卡秒，与样本对照一致，月报返回相同的 GPU 集合。隔离回归 135 通过、1 跳过。

实机样本验证了残留记录并存的处理。受控同卡跨克隆换绑、正式 Compose 启停和长期采样仍待验证。下一阶段交付现有 MaaS 入口下的只读网页与 JSON 查询。

## 第三阶段运维查询

网页为 `GET /maas/ops/gpu-time`，JSON 为 `GET /maas/ops/gpu-time/report`。两个入口复用 MaaS API 和网关，可选 `period=YYYY-MM-DD` 或 `period=YYYY-MM`，默认北京时间当天。可用 `gpu_uuid` 精确筛选。页面和 JSON 共用 CLI 的 PostgreSQL 只读查询，显示最近成功采样和数据过期状态。

现有 MaaS Bearer 绑定用于模型调用。E17 使用专用 HTTP Basic 运维凭据，用户名为 `e17`，密码从 `E17_QUERY_KEY_FILE` 读取。默认未配置时查询关闭。部署时在现有私有 secrets 目录放置容器 UID 10001 可读的查询密钥，将该环境变量设置为容器内文件路径，例如 `/run/secrets/e17-query-key`，并应用新版 API 和网关配置。浏览器通过私有 TLS 或受控 SSH 转发访问。GPUStack 列表凭据仍由采样容器持有。

查询阶段交付代码和隔离测试。正式环境网关验收与启动采样安排在部署阶段。

## 第四阶段部署验收

001 已启用 E17。部署镜像 `cybercafe-maas-tasks:e17-r1` 基于当时线上 `ocr-metering-r2`，仅叠加 E17 模块、路由和数据库迁移，保留现网客户 API 契约。应用了 PostgreSQL 迁移 007，更新了 MaaS API 容器及私有 TLS 网关配置，启动了独立采集容器，8 个执行器仍在运行。

私有 TLS 实测网页和月报 JSON 返回 200，匿名和推理 Bearer 凭据均返回 401。连续两轮采样后，日报显示 4 个 GPU UUID、累计 120 在线卡秒，最新采样未过期。HTTP 入口继续按原边界开放。首次上线尝试在入口检查失败后完成回退，修正私有 TLS 查询参数放行并等待网关重载生效后发布成功。

从 Mac 经现有控制节点 SSH 配置转发私有 TLS 端口后访问网页。查询用户名为 `e17`，密码保存在 Mac 的私有部署目录，使用已信任的 MaaS 私有证书。

```bash
ssh -N -F .maas/ssh/config -L 18832:127.0.0.1:18832 maas-controller
```

浏览器打开 `https://127.0.0.1:18832/maas/ops/gpu-time`。历史从本次正式采样开始。受控同卡跨克隆换绑和线上停采恢复演练仍待验证。

### HTTP 与 HTTPS 查询入口

E17 网页和 JSON 查询同时经现有 HTTP 18831 和私有 HTTPS 18832 提供。下游容器可通过已放行的 MaaS 容器网络访问 HTTP 入口，沿用专用 Basic 运维凭据。Mac 可经 SSH 将本机回环 18831 转发到 001 的回环 18831 后访问页面。已验证 Mac HTTP 隧道和下游容器网络的网页及月报 JSON 均返回 200，下游匿名请求返回 401。HTTP Basic 凭据在 HTTP 链路上不加密，HTTP 仅用于受控网络或 SSH 隧道。

### 采样覆盖率与连续区间

总体覆盖率为查询窗口内有效采样秒数除以窗口秒数。已结束的日/月使用完整自然日/月，当前日/月截至查询时刻。相邻两轮都成功、处于同一采样会话且间隔不超过 120 秒时，两轮之间计为有效。报表从持久化样本推导连续区间，合并相接的有效段，并裁剪到查询窗口。失败轮次、停采、首次采样之前及最后成功样本之后尚未确认的时间均不计入有效秒数。当前沿用严格的双样本规则，单次失败即可切断有效区间。

逐卡在线和非 ready 来自能够明确归属的 worker 状态。逐卡未知等于查询窗口减去在线及非 ready 时长。总体采样成功期间，个别 GPU 未上报或归属冲突仍会记作该卡未知。

2026-11-04 已在 001 发布覆盖率页面。API 镜像 `e17-coverage-2e39f1b` 基于线上 `8f482ac` 更新查询模块。通过 HTTP 网关实测页面和月报 JSON，月报有效秒数等于各区间之和，且与未覆盖秒数相加等于查询窗口。采集容器持续运行。

### 自定义查询时间范围

网页使用两个日期时间控件，按北京时间解释输入。默认查询最近 24 小时。自定义区间使用包含开始、不含结束的口径，结束时间超出当前时刻时只统计到当前时刻。GPU UUID 支持忽略大小写的子串匹配，筛选仅影响逐卡列表，总体覆盖率仍基于完整查询窗口。

JSON 查询接受 `start=2026-11-04T00:00&end=2026-11-05T00:00`，必须成对提供且开始早于结束。原有 `period` 日月参数可继续单独使用。

2026-11-04 已在 001 发布自定义时间范围与 UUID 模糊查询，API 镜像为 `e17-range-a42a108`。通过 HTTP 网关验证时间控件、默认 86400 秒窗口、显式起止区间、UUID 子串和原月报。采集容器持续运行。

报表增加全部 GPU 在线时长合计。JSON 的 `total_online_gpu_seconds` 为查询时段内所有卡的在线秒数之和，网页同时显示卡小时。UUID 筛选只影响逐卡列表。

2026-11-04 已在 001 发布全部 GPU 在线时长合计，API 镜像为 `e17-total-72d45b9`。实测网页与月报 JSON，合计等于逐卡在线时长之和，UUID 筛选为空时合计仍一致。采集容器持续运行。

## 待讨论：注销长期非 ready 的 GPUStack worker

长期非 ready 只作为筛查条件。首轮候选限于管理员明确确认已回收的克隆，按 worker ID 逐条核对，避免把同一 GPU 上的新克隆当成旧记录。暂时故障或回收情况不明的节点保留恢复机会。

GPUStack v2.2.3 的 worker 删除事件会批量删除匹配的模型实例。需检查主 worker 和分布式副本的下属 worker 引用。副本数可能变化，补副本取决于部署目标和剩余可调度容量。带 external_id 的 worker 走软删除并进入 deleting，应单独核对基础设施回收流程。还需核对现有维护绑定、节点保护规则、监控目标及旧 worker 重新注册行为。

删除 GPUStack worker 后，E17 仍保留已有快照和 UUID。未来样本若缺少该 UUID，按现有规则计为未知。同卡新克隆上报相同 UUID 时可以续计。若要区分已回收和未知，仍需独立生命周期标记。

验证顺序为只读列出候选和关联副本、维护绑定及容量，保存删除前证据，再在独立环境对无关联副本的已回收 worker 验证单条删除。核对其他 worker、副本、路由、同步和异步 OCR、监控及 E17。涉及分布式或外部供应节点的情况单独验证。当前仅登记讨论。

# E17 GPU 每日与每月在线时长

## 需求与实施计划

1. 使用 GPUStack v2.2.3 的分页 worker 列表读取状态和 GPU UUID。按 UUID 汇总同一张卡在不同克隆上的记录。worker 名可以携带 UUID 方便核对，统计以控制面上报的 UUID 为准。
2. 运维通过独立定时任务采样，使用独立 SQLite 文件。建议每分钟采样一次，连续有效样本的最大间隔为 120 秒。部署前验证 UUID 跨克隆稳定性及列表权限。
3. 按北京时间自然日查询在线、非 ready 和未知秒数。前一有效样本代表到下一有效样本前的区间；采样失败、过长间隔、卡未上报或 UUID 冲突的区间归为未知。验证旧 worker 记录残留对统计的影响。
4. 增加北京时间自然月查询，将每日时长按 GPU UUID 累加。用固定时间戳验证跨日和月末切分。
5. 在独立状态库完成实机试采，验收后再启用定时采样并开始积累历史。

范围以 GPU 在线时长为限。模型部署时长已移出 E17，下一版采样只读 worker 列表，查询也移除模型时长字段。

## 当前实现与验证状态

首版运维 CLI 已实现日报，当前仍读取模型副本列表并输出模型相关统计。采集与查询的收敛、月报和定时部署待完成。此前使用现有推理凭据试采收到 HTTP 错误，下一次实机验收需验证 worker 列表权限。

```bash
python3 -m maas_platform.gpu_time --db /var/lib/maas-ops/gpu-time.sqlite report 2026-11-04
```

报告列出截至统计期末已观测到的 UUID，当天统计截至查询时间。最后一个样本之后的区间在下一次有效采样前计为未知。

## 2026-11-04 阶段性决议

- **统计口径**。按控制面上报的 GPU UUID 汇总北京时间自然日与自然月的在线、非 ready 和未知时长。在线指 GPU 被上报且 worker 为 ready。当日和当月截至查询时刻。模型部署时长、推理忙时和利用率移出 E17。
- **采样与归属**。只读取 GPUStack worker 列表。建议每 60 秒采样一次，两个相邻样本均有效且间隔不超过 120 秒时，用前一样本估算该段状态。采样失败、超长间隔、未上报或无法判定归属计为未知。同一 UUID 唯一 ready 的记录可在实机确认旧记录已退出 ready 后接续计时，多条同时 ready 计为未知。worker 改名无需作为前置条件。
- **查询入口**。保留 CLI，新增独立只读网页和 JSON 查询。网页支持日/月选择、GPU UUID 筛选，展示三类时长与最近成功采样时间。三种入口共用同一计算口径，月报按日累计。
- **部署与操作**。拟在 XZ-31-001 部署独立 systemd 定时采样和查询服务，共用独立 SQLite。仅采样服务持有 GPUStack 凭据，查询服务以只读权限访问库并监听回环地址。运维先通过 SSH 转发访问网页，若需多人共享，再接入带鉴权的内部入口。采样与查询均独立于推理请求。
- **前置条件与验收**。先用运维凭据在独立库确认 worker 列表权限，连续试采并对照 GPUStack 页面。用独立克隆验证同卡跨克隆 UUID 稳定性及旧记录残留。用固定时间戳覆盖跨日、跨月、采集断档和冲突，核对三类时长之和、月报与逐日汇总。用同一测试库对比 CLI、JSON 和网页，检查筛选、空数据和采集异常提示。
- **交付顺序**。收敛 worker 采样并补齐月报，完成独立库实机试采，再交付只读网页与 JSON 查询，最后在 001 启用定时采样。网页可先用测试库开发验证。本决议记录后续实施范围，线上历史从正式采样开始积累。

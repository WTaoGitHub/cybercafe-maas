# 新VPC首启与冷模型串联验收：控制端准备

2026-11-13 · 工具候选已实现，控制端准备待核对 · [Issue #39](https://github.com/WTaoGitHub/cybercafe-maas/issues/39)

用户明确下一轮由管理员提供新VPC验证自动接入，不再优先在旧002上手动恢复。代理只准备控制端试点/观测，不执行或自动化既有VM关机、重启、重建、还原。新节点首启注册保持正常流程，不能为取得冷样本改为人工注册。

## 两个阶段与两道闸

第一阶段是新VPC启动、配置和worker自动注册，第二阶段才是模型首次拉取与启动。注册失败则冷测试为未执行，不混成镜像拉取失败。控制端先开始独立有界观测，冷部署保持replicas0、策略Observe、ownership暂停；选择器使用不匹配当前worker的占位值。仅新增worker不会让已经达max2的正式OCR自动扩大，本试点需要自己的目标缺口和授权。

节点Ready后，按实际worker ID/GPU UUID及标签绑定试点，不能沿用旧002身份。绑定选择器是明确记录的试点准备操作，调节器本身只修改replicas。只读SSH取一次镜像/目标模型文件缓存及启动ID，并以控制端时间记录证据，随后才允许Apply自动0→1。取证间隔单独记录，不算成调节器响应延迟；模型计时起点采用Apply，可与同节点热对照一致比较。

## 工具与边界

`maas_platform/replica_cold_trial.py` 提供min1/max1、串行上限1、Observe默认策略及单次写入拦截。默认观测模式拒绝全部非GET；显式cold模式还需：

- 私有`cold-proof.json`与test_id/model_id/固定镜像digest一致，来自认证SSH；控制端取证时间不超过300秒且不在未来。
- 目标镜像、目标模型文件均未缓存，保留原始清单SHA256及启动ID；新节点不属于受保护worker/GPU。
- 原生worker在正确集群Ready、非maintenance、单卡UUID与证据一致，worker-name标签与选择器一致。
- 新鲜模型仍0/0、3.5GiB声明、正确归属/部署ID，配置完全保持，只允许0→1；注册引擎仍为冻结digest。
- 发送前持久化独占`one-shot-intent.json`，永不自动删除。重试、归零重拉、跨模型、改配置及二次发送均拒绝；未知结果只读核对，不能自动重放。

`scripts/maas/replica_cold_session.py` 复用生产worker/实例订阅、模型事件和持续对账，观测只写独立私有文件，不竞争正式E17 PostgreSQL锁。原生完整列表用于规划；记录语义转换和最新摘要，保留源读取时间，不把不同列表声称为原子全局快照。单次窗口60～7200秒，默认2小时，到期自然停止，restart=no；没有到时自动启动模型的功能。此为有限验收工具，不是新的常驻collector，不增加生产请求SSH门禁。

所有连接、spec、证明、状态与日志仅在私有目录；目录700/文件600，运行用户10001。独立挂载原生管理凭据，但MaaS运行时仅授权一个测试模型、上限1，另有传输拦截；这不冒充原生管理key具有同样细粒度限制。原生推理使用限定测试路由的短期inference key，不能用管理key替代。

## 控制端资源与下游验收

准备专属原生部署/路由和推理key，先保持0/0，无模型实例。MaaS侧采用同镜像的隔离测试API/单执行器、专用逻辑模型与凭据绑定、独立PostgreSQL数据库和文件目录；测试API仅回环监听，不修改常驻catalog、项目、鉴权或对外入口。只有通过该测试逻辑模型完成的任务才算冷节点MaaS闭环；正式ocr.default请求仅作原业务回归。

API迁移及空队列执行器可准备，但不提前提交推理任务。先验证health、能力查询和零任务/零成功计量；worker Ready与模型Ready后再提交一笔唯一幂等键的真实任务。测试数据库复用现有PostgreSQL进程不等于共用生产数据库，凭据只获测试库权限；不新增公网端口。

## 管理员提供新节点前后

准备完成后再通知管理员提供新VPC。备用管理路径已只读验证；窗口到期前未开始可重新显式开新的有界窗口，不自动续跑/重发。新快照是否含注册修复、OCR/辅助镜像缓存必须现场确认。本工具不保证同母版的新VPC一定无镜像层缓存，也不把缺手动启动许可当成自动模式故障。

冷启动上界按实际镜像体积/带宽和初始化余量、在Apply前冻结，不能沿用热测试180秒；不能中途扩大。异常最多两次有界诊断，仍不通则停止保留，不清UNKNOWN或未知journal，不重启VM/worker/Docker解决。

本轮控制端准备不等于已验证新VM首启、冷拉、实际容器GPU或冷OCR。真实条件就绪后才执行绑定/取证/放行与热对照；两个全冷节点上限1/2对比另需独立冷环境。[冷验收计划](REPLICA-COLD-VALIDATION.md)。

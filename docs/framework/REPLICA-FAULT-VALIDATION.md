# 调节器故障与恢复实测

2026-11-12 · 工具与本轮五项真实执行均已验收 · [Issue #39](https://github.com/WTaoGitHub/cybercafe-maas/issues/39)

本轮补当前调节器的故障正确性，不开展恢复速度调优。正式 GPUStack、MaaS API/E17 及 worker 均不重启、不切换配置。选择一个当前为 0/0 的独立试点部署，明确指定另一个受保护的正式部署，执行前后核对其配置、Ready 和实例 ID。

## 工具与边界

`maas_platform/replica_fault_proxy.py` 是显式调用的隔离试验工具，生产 API/E17 不加载它。临时监听只绑定本机回环的随机端口，读取原生管理凭据，只转发原生列表/模型读取及指定试点从 0 到 1 的严格更新；其他模型、删除、创建和普通配置修改均拒绝。日志不包含凭据。故障开关仅由拥有代理的测试进程直接设置，没有网络控制入口。

`scripts/maas/replica_fault_live.py` 使用当前生产订阅、完整分页查询、对账、写入器和持久状态代码。试点调节器在独立 OS 子进程中运行，可用 SIGTERM 自然退出并以相同状态目录重新启动。只隔离 E17 的观测持久化输出，不占用正式日报数据库/采样锁；不宣称本轮覆盖 E17 数据库故障。正式调节器继续使用原来的原生端点和状态目录，不经过代理。

每个案例使用新的私有目录和独立策略、授权、journal、ownership、status。输出目录必须事先不存在，且权限 700，文件 600。基线必须是试点 0/0，试点与受保护部署不能相同。镜像和权重可复用，不更改模型配置。试点清理是明确记录的测试运维操作，不是调节器自动归零。

## 验收矩阵

| 案例 | 注入与预期 |
| --- | --- |
| watch_down | 中断现有订阅并拒绝重连，完整读取仍可用：转入 polling_fallback，仍只扩一次；恢复后订阅重连，不重复写入 |
| reads_down | 完整资源/模型/实例读取返回 503：快照无效，零写入；恢复后用新鲜完整快照自动继续 |
| incomplete_lists | 列表总数与实际条目不符：生产分页读取拒绝，不能用部分数据规划；恢复后正常继续 |
| after_commit | 原生确实执行 0→1，但代理不转回响应并阻断确认读取：保留 journal，resume 拒绝；真实重启试点调节进程不重发；恢复读取后在暂停期间只读确认，自动清除已确认 journal，原生 PUT 仅一次 |
| before_commit | 试点请求到达代理但不转发原生，同时确认不可用：保留未知 journal；重启、恢复读取后即使仍读到旧目标 0，也不能证明未执行，必须继续保留、拒绝 resume、不重发；最终暂停/Observe，并保留独立试点证据 |

每个案例都核对代理收到/转发/确认原生成功的次数及受保护服务不变。最后一个案例故意留下试点待确认日志，不能为了报告全绿而手工删除、重新接管或重放请求。它不属于正式调节器的 journal，不阻塞正式服务。

## 操作要求

使用当前已固定的 MaaS 镜像，在独立临时容器中设置 `PYTHONPATH=/app`，挂载上述工具和专用私有输出目录，沿用只读管理 key 与 catalog。显式指定 `--trial-model`、`--protected-model` 和新的 `--output`。仅临时代理和试点进程运行在该容器，restart=no；不替换任何常驻容器，不修改 worker 网络规则。

正式执行前先适当回归工具并保存新鲜基线到 Mac。每一条件有有限等待，未知结果不重发。遇到异常最多两次有界诊断，仍不能继续就停下并保存失败现场；不得通过重启 VM、worker、Docker 或清理未知日志恢复。执行后核对正式副本、原生插件 Observe、MaaS OCR/唯一计量、E17 采样与日报、UNKNOWN 及正式待确认日志，归档真实私有证据，公开报告只放脱敏结果。

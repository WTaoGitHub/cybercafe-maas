## 范围和完成口径

**本功能只负责worker VPC启动时准备宿主`/srv/maas/models`的本地automount，首次实际访问时才连接远程NFS进行只读挂载，并交付相应母版与快照。** 用户指定新PC目录为`/root/maas/data/modelsWeights`；入口准备、实际来源/ro/读取分别取证。服务端可用的只读export由管理员提供；本功能不新增管理员模型发布系统。

模型服务副本的容器创建、目录映射、模型加载路径、版本/缓存配置、标签/选择器、真实推理及模型迁移归模型部署业务，本计划不实现或验收。完整镜像与外置文件仍是两种正式部署方式，不要求提取镜像权重到NFS。当前Unlimited-OCR-2继续读取worker本地目录，旧OCR继续使用镜像内权重；本功能不改变这些运行部署。CPU推理仍由[Issue #61](https://github.com/WTaoGitHub/cybercafe-maas/issues/61)独立跟踪。

完成必须同时具备：服务端export与网络交接、宿主自动挂载及故障校验、新版母版文件清单、实际快照版本、独立新VPC零手工补配置首启挂载证据、小批应用和存量维护记录、软件/配置回退材料。单节点手动挂载、母版静态检查或平台“保存成功”各自只能证明对应阶段；容器和模型可用性不属于完成条件。

沿用已有母版交接分工：[E5管理员交接点](E5-TEST-DEPLOYMENT.md#管理员交接点2026-10-23确认)及[母版操作手册](../../deploy/bootstrap/clone/MANUAL-TOWER-DEPLOYMENT.md)。目前实际新快照保存、选择/应用快照、创建并首次启动独立VPC由平台管理员操作；我们负责软件、母版准备、交接清单和真实验收，不假定已有供应商平台API或操作权限。

## 分阶段实施

| 阶段 | 主要操作 | 负责人 | 退出条件 |
| --- | --- | --- | --- |
| 1. 基线与可达性 | 只读核对新PC存储/文件系统/NFS能力、worker拓扑、实际母版入口、原配置/身份/运行实例和平台快照应用规则 | 我们，平台信息由管理员确认 | 固定网络、目录、版本及可回退基线；直接数据通道可用 |
| 2. 测试export与交接 | 服务端管理员提供独立只读export、允许的网络和读取用户、固定测试文件及摘要；客户端核对可达性 | 服务端管理员，我们配合 | 目录可读，服务端拒写，暂存目录及凭据不导出 |
| 3. 客户端与独立试点 | 在用户指定的无业务001使用独立目录，验证本地automount准备不访问远端，再单独验证首次访问、ro、幂等及异常 | 我们 | 入口准备和实际NFS读取均有独立证据；不覆盖已有模型目录、不重启VM；旧本地流程与GPU UUID链路兼容 |
| **4. 母版实际更新** | 在核验过的母版安装NFS客户端依赖、新模块/单元、配置引用及信任材料；备份并记录文件摘要和启用关系 | **我们** | 形成可制作快照的安装清单，母版保护有效、无实例身份/认证污染 |
| **5. 保存与应用新快照** | 管理员保存新版，记录真实平台快照ID/版本；指定该版本创建并首次启动独立VPC A/B | **平台管理员** | 平台操作与版本有据可查，提供实例/快照关联及受控访问方式 |
| **6. 新快照首启验收** | 无手动mount/apply或复制文件补救，核对首启自动准备automount且准备过程不主动访问NFS，区分其他进程触发的实际访问，核对既有自动注册链 | **我们，管理员交付实例** | A/B使用指定快照；自动入口和首次NFS只读读取分开取证；001不通过VM重启补做首启 |
| **7. 小批应用与存量维护迁移** | 新建节点小批选择已验收快照；存量节点按维护窗口更新宿主引导和配置，核对目标目录占用及回退 | **平台管理员与我们按操作边界协作** | 每批文件版本、宿主挂载及回退状态可核对；不覆盖业务正在使用的目录 |
| 8. 运维交付 | 交付NFS配置、挂载检查、故障处理、软件/配置回退及母版/快照关联手册 | 我们 | 安装、保存快照、应用、首启和推广证据分别可查，不以模型业务验收替代 |

前一阶段未通过时不推进依赖阶段。尤其先完成独立试点，再改母版和制作快照，避免反复封版。平台操作等待单独记录，不把缺少快照或实例交接写成首启已通过。

阶段1记录宿主目标目录的现有文件和业务占用，避免将已有本地权重直接遮蔽。阶段2消费管理员已提供的export，不实现导入/发布/回收应用。阶段3和6只验证宿主文件读取，无需创建推理容器或部署模型。模型服务如何消费该目录由部署业务另行安排。

## 客户端实现与验证范围

优先扩展现有宿主准备模块，实施前核对调用链：

- `maas_bootstrap/client.py`与配置发布/读取服务：明确允许的NFS服务端、export、目标目录及只读选项，验签和本地允许策略双重约束；保持旧配置兼容。这里的配置发布不指管理员模型文件发布功能。
- `maas_bootstrap/storage.py`、`nfs.py`：NFS模式只在启动准备受控systemd automount，检查本地元数据，不读取远端文件或写marker。显式`storage-check`才触发真实挂载和测试文件摘要检查，区分已准备和已验证；保留本地模式和本地缓存，不要求逐模型manifest。
- `maas_bootstrap/worker.py`中的`storage.prepare/status`调用：仅核对其与宿主只读检查兼容，不扩展worker/推理容器挂载布局、环境或模型配置，不新增GPUStack标签/选择器。
- `maas_bootstrap/startup.py`、相关systemd单元和`scripts/maas/prepare_worker_image.py`：更新首启顺序及母版交付文件清单，记录有限重试、阶段耗时和失败原因。
- 对应`tests/bootstrap`中的配置、storage、startup、image/bundle及直接调用方回归；保留GPU UUID、自动预登记/发证及母版保护。真实Linux挂载和首启另做环境验收，不测试推理请求或副本扩容。

保留2026-11-11已交付的[延后启动机制](../../results/maas-e5-late-startup-20261111/REPORT.md)：基本系统启动和供应商命名先完成，再由延后的一次性准备任务执行网络边界及按节点模式的存储准备，之后申请GPU UUID许可、启动worker。NFS节点先准备本地automount，启动不要求实际NFS连接；仅镜像节点不要求NFS。保留现有600秒准备总预算和620秒单元超时，不增加NFS读取等待。

NFS节点的本地automount准备加入上述有限准备链，在worker启动和短期许可前完成，不主动访问远端；失败停止本次准备，不自动改成本地模式。本功能不负责存储能力标签。首次NFS挂载使用systemd单元的20秒启动超时和一次启动限制，不自动清除失败状态。客户端显式读取检查使用有界子进程，超时保留私有操作记录。hard NFS内核I/O可能不随超时退出，真实故障仍须独立实测，不以kill成功证明已释放I/O，不加入VM自动重启。

## 母版更新、封版和平台应用操作

### 更新母版前

1. 根据当前管理员交接核验真实母版角色、平台镜像关系及入口。历史名称、地址、端口和过去的快照备注只能作线索，不能据此修改当前在线worker。
2. 备份原模块、单元、启用关系和受控配置到私有操作目录；固定本次Git提交、公开交付包SHA、依赖版本及回退清单。
3. 核对母版保护有效、无业务模型实例，不在母版调用worker的真实`apply`、自动预登记或发证。001的普通worker角色不变，不能沿用旧控制平面阻断规则。

### 实际安装及封版检查

1. 安装已验证的NFS客户端依赖及引导代码、准备统一挂载点和本地缓存路径；按交付清单原子更新文件并核对权限和摘要。保留现有驱动/CUDA、供应商命名和合法的信任初始化流程。
2. 配置稳定服务寻址、受控NFS策略引用和逻辑`image_id`兼容关系；普通worker不得读取管理员发布凭据。保留GPU UUID作为name/external_id及现有自动预登记/发证方式，不部署旧退役插件。
3. 核对systemd单元及timer启用关系；母版只安装/静态检查，不使用`--now`启动worker链，不为测试重启母版或现网VM。必要的真实启动测试在后续独立新VPC完成。
4. 模板保持必要的客户端配置与信任材料，但不包含某台worker的实际GPU UUID、原生token、设备私钥/设备证书、已签发许可、会话状态、applied/maintenance记录或Registry发布认证。不得从运行worker整体复制状态目录进入母版。
5. 确认没有仍运行的试验容器、试验NFS挂载或身份/认证残留；不预装全部模型权重，不把挂载会话当作克隆已经具备自动挂载的证据。
6. 出具“可制作快照”交接清单；在实际安装清单及保护检查完成前，不通知管理员保存原样快照作为本次新版。

### 管理员平台操作与版本登记

管理员在平台保存新版快照，按已核对的供应商流程将其指定给独立VPC A/B，并创建、首次启动这些测试实例。至少分开登记：

| 标识 | 含义 |
| --- | --- |
| Git提交 / 交付包SHA | 客户端及单元的实际软件版本 |
| 逻辑`image_id` / 配置revision | Bootstrap兼容与签名发布范围 |
| 平台snapshot ID / image版本 | 供应商实际保存、选择和应用的快照 |
| NFS服务端/export / 测试文件摘要 | 宿主实际挂载来源与读取一致性依据 |

不能把更新逻辑`image_id`、保存本地tar包或平台显示相同备注当作新版快照已应用。管理员交付A/B与真实快照版本关联、GPU分配信息及安全访问方式；原始连接信息、凭据、设备/启动标识留在私有证据中。

更新母版或保存快照本身，不作为已经运行的存量VPC已更新的证据。先核对平台生效规则；本计划的新快照应用首先面向明确选定该版本的新VPC，存量节点另走维护迁移。

## 新快照首启与故障验收

首启证据采集前不手工运行mount、bootstrap apply或复制权重。记录供应商命名完成、系统基本启动、延后任务、配置获取、所选存储模式准备、GPU UUID许可和worker Ready的实际时序。若人工恢复后成功，保留首次失败，不能改写为零干预首启成功。

- **独立性与继承**：A/B确实使用指定的新快照；各自GPU与身份关联正确，未携带母版或另一节点状态，不以此证明双卡模型容量。
- **按需准备与首次访问**：先证明准备代码仅建立本地autofs入口，未主动连接NFS或读取文件；其他进程（包括Docker路径检查）的实际访问也会触发挂载，应记录触发时序，不能要求或宣称首启全程零连接。再独立显式访问，证明目标为指定服务端/export、NFS类型与ro正确、测试文件摘要匹配。服务端拒写使用独立export取证，不修改已发布模型。空目录和autofs均不能冒充真实读取成功。
- **有限并发与耗时**：单节点通过后核对两节点自动挂载与同一测试文件读取，记录挂载/检查耗时和网络读量，不进行模型加载压测。
- **异常和恢复**：仅在试验export/试验节点验证NFS不可达、错误来源、错误挂载选项、文件不可读或摘要不符、配置不兼容及恢复后接续；不停止共享NFS。记录卡住的I/O和尝试次数，不通过自动重启恢复。
- **幂等和既有链路**：首启证据采集后再重复apply，确认不重复/叠加挂载、不创建第二个worker；GPU UUID预登记、发证、母版保护及未配置NFS的流程保持兼容。

本功能验收到宿主目录可用为止，不创建模型服务副本，不核对容器内目录，不执行真实推理、页收据、模型冷拉或增副本测试；这些属于后续模型部署业务。

启动失败时停在当前阶段，保存故障、尝试次数及现场；不得通过重启XZ-31-001/002、切系统或恢复镜像“修复”。需要再次首启时，由管理员另行提供获准的新建可销毁实例，不操作受保护VM。

## 分批应用、存量迁移与回退

1. 新快照首启门槛通过后，管理员先对小批新VPC指定该快照；我们核对实际文件版本、宿主挂载及读取行为，再推广后续批次。不得仅因管理员已选择快照就记为应用验收通过。
2. 存量worker先核对目标目录的本地文件、挂载和业务占用。若正在使用则暂不覆盖挂载，由业务方按现有维护能力安排窗口；不在本功能中增加排空或模型迁移逻辑。
3. 保留原本地权重、配置和身份状态，只更新宿主引导及受控NFS配置。确认不会遮蔽现有业务目录后才应用并验收宿主挂载，不修改容器布局或模型来源。
4. 软件和配置回退使用本阶段旧包及配置；解除挂载前核对占用，忙碌或卡住时保留现场，不盲目强制卸载。母版/快照发布失败时保留旧快照供后续新实例使用，存量VM不通过还原快照回退。
5. 管理员模型发布、版本回退和引用保护回收沿用独立管理流程，本功能不删除模型文件或Registry镜像。

XZ-31-001、XZ-31-002全程禁止整机重启、重建/还原、切系统等等效操作。它们若参与存量维护，也仅按现有允许的进程/容器操作执行；没有做的整机验证不写为已完成。

## 最终交付

发布可追溯的NFS服务端/export交接、受控宿主挂载配置、客户端交付包、母版安装清单、平台快照关联、A/B首启挂载与读取证据、小批/存量维护记录，以及挂载故障和软件/配置回退手册。证据中区分计划、已安装、已保存快照、已应用、已验收，逐阶段更新Issue #6。交付不包含管理员模型发布应用、推理容器配置或模型部署验收。

本计划不承诺未经实测的网络带宽、千节点同时加载性能、存储高可用、百页推理或CPU性能。新PC的磁盘和网络仍是共享依赖；阶段1先确定实际能力和边界，再冻结实施参数。

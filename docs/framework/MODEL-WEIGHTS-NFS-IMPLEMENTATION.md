# 集中模型权重库实施与母版快照应用计划

2026-11-17 · [目标架构](MODEL-WEIGHTS-NFS.md) · [Issue #6](https://github.com/WTaoGitHub/cybercafe-maas/issues/6)

**本计划包含实际更新母版、保存新版快照、将新版快照应用于独立VPC及分批推广。** 仅安装客户端文件或手动挂载NFS不能算完成。当前状态为计划已制定，以下阶段均未执行；本轮没有连接或修改母版、新PC服务、worker或平台快照。

## 范围和完成口径

新PC集中保存全部已发布模型，管理员维护不可变版本，获准worker只读挂载全库，GPUStack使用统一固定`local_path`启动模型实例。首个闭环使用现有Unlimited-OCR-2固定版本，随后迁移旧OCR镜像内的权重；CPU转换格式可沿用同一发布机制，CPU推理部署仍由[Issue #61](https://github.com/WTaoGitHub/cybercafe-maas/issues/61)独立跟踪。

官方镜像已含权重时，先按[内置权重兼容规则](MODEL-WEIGHTS-NFS.md#官方镜像内置权重的兼容)核对真实入口和加载路径：能指定外部路径者显式读NFS，固定内置者先保持已核验模式、另行适配。记录实际来源，不把挂载全库、归档镜像权重或GPUStack的登记路径当作已经从NFS加载；兼容内置模式不自动解除全模型迁移目标。

完成必须同时具备：集中模型库和管理功能、受控网络及只读导出、自动挂载引导、新版母版文件清单、实际快照版本、独立新VPC零手工补配置首启证据、小批应用和存量迁移记录、回退材料。单节点手动试验、母版静态检查或平台“保存成功”各自只能证明对应阶段。

沿用已有母版交接分工：[E5管理员交接点](E5-TEST-DEPLOYMENT.md#管理员交接点2026-10-23确认)及[母版操作手册](../../deploy/bootstrap/clone/MANUAL-TOWER-DEPLOYMENT.md)。目前实际新快照保存、选择/应用快照、创建并首次启动独立VPC由平台管理员操作；我们负责软件、母版准备、交接清单和真实验收，不假定已有供应商平台API或操作权限。

## 分阶段实施

| 阶段 | 主要操作 | 负责人 | 退出条件 |
| --- | --- | --- | --- |
| 1. 基线与可达性 | 只读核对新PC存储/文件系统/NFS能力、worker拓扑、实际母版入口、原配置/身份/运行实例和平台快照应用规则 | 我们，平台信息由管理员确认 | 固定网络、目录、版本及可回退基线；直接数据通道可用 |
| 2. 服务端与发布管理 | 建立staging/releases、受控管理员发布/校验/回退/引用保护回收、只读NFS测试export；导入固定Unlimited-OCR-2版本并逐文件核对 | 我们 | 管理操作可追溯，已发布目录不可原地覆盖，worker无法写入，备份可恢复 |
| 3. 客户端与独立试点 | 扩展签名配置和本地允许策略、NFS模式引导、只读状态校验和本地缓存；在无业务worker独立目录验证调度及推理 | 我们 | 正常和失败路径通过，GPU UUID注册及既有本地存储模式回归通过 |
| **4. 母版实际更新** | 在核验过的母版安装NFS客户端依赖、新模块/单元、配置引用及信任材料；备份并记录文件摘要和启用关系 | **我们** | 形成可制作快照的安装清单，母版保护有效、无实例身份/认证污染 |
| **5. 保存与应用新快照** | 管理员保存新版，记录真实平台快照ID/版本；指定该版本创建并首次启动独立VPC A/B | **平台管理员** | 平台操作与版本有据可查，提供实例/快照关联及受控访问方式 |
| **6. 新快照首启验收** | 无手动mount/apply/cp/pull补救的情况下，核对开机时序、NFS、自动注册、模型调度和实际任务 | **我们，管理员交付实例** | 两个独立worker从同一快照自动获得同版本模型库，并完成真实推理 |
| **7. 小批应用与存量迁移** | 新建节点小批选择已验收快照；存量worker按现有维护能力逐个排空、更新挂载布局、核验身份及恢复服务 | **平台管理员与我们按操作边界协作** | 每批版本/服务/回退状态可核对；没有靠重装现网VM迁移 |
| 8. 旧权重迁移与交付 | 将旧OCR的ONNX权重独立发布并调整加载路径；补管理、故障、备份恢复及回收手册 | 我们 | 目标范围内全部模型使用集中库，旧版本和旧镜像按引用保护退役 |

前一阶段未通过时不推进依赖阶段。尤其先完成独立试点，再改母版和制作快照，避免反复封版。平台操作等待单独记录，不把缺少快照或实例交接写成首启已通过。

阶段1逐模型登记镜像digest、是否内置权重、真实读取目录、外部路径参数是否生效、启动是否写模型目录/下载文件，以及代码与权重兼容关系。阶段2可从固定镜像提取并核对配套文件后发布；阶段3测试显式NFS路径及完整文件，避免挂载遮蔽模型代码、配置或tokenizer。阶段8保留所有尚未完成外置的模型清单；挂载覆盖不缩小原镜像体积，不将镜像瘦身作为NFS挂载已实现的附带成果。

## 客户端实现与验证范围

优先扩展现有模块，不新增模型调度器：

- `maas_bootstrap/client.py`与发布/配置服务：明确允许的NFS服务端、export、目标目录、只读策略及库manifest，验签和本地允许策略双重约束；保持旧配置兼容并显式声明新版镜像兼容范围。
- `maas_bootstrap/storage.py`：区分本地发布与NFS只读模式；NFS模式验证真实挂载来源、类型、ro、版本和必要文件，不创建远端目录/marker，不接受空本地目录冒充共享库。
- `maas_bootstrap/worker.py`：宿主、原生worker、推理容器同路径只读可见，本地缓存可写，身份及认证目录继续排除；挂载布局变化遵守已有维护保护。
- `maas_bootstrap/startup.py`、相关systemd单元和`scripts/maas/prepare_worker_image.py`：更新首启顺序及母版交付文件清单，记录有限重试、阶段耗时和失败原因。
- 对应`tests/bootstrap`中的client、publisher/service、storage、worker、startup、image/bundle、registry、handoff、auto_enrollment验证；实际Linux挂载及GPUStack推理另做环境验收。

保留2026-11-11已交付的[延后启动机制](../../results/maas-e5-late-startup-20261111/REPORT.md)：基本系统启动和供应商命名先完成，再由延后的一次性准备任务执行网络边界及配置/NFS准备，之后申请GPU UUID许可、启动worker。NFS依赖只约束worker启动，不能成为`multi-user.target`、基本网络或Docker启动的前置条件。现有600秒准备总预算、子阶段预算和620秒单元超时作为基线，若需调整先测量并明确记录，不无限增加等待。

NFS挂载与检查加入上述有限准备链，须在启动worker和申请短期启动许可前完成。默认hard NFS的内核I/O可能不随应用超时退出：不可达与卡住的场景必须在独立环境验证，不能仅以进程超时/kill成功作为已释放I/O或可以重试的证据。首轮保留“停止新尝试、保留现场”的处理，不加入VM自动重启。

## 母版更新、封版和平台应用操作

### 更新母版前

1. 根据当前管理员交接核验真实母版角色、平台镜像关系及入口。历史名称、地址、端口和过去的快照备注只能作线索，不能据此修改当前在线worker。
2. 备份原模块、单元、启用关系和受控配置到私有操作目录；固定本次Git提交、公开交付包SHA、依赖版本及回退清单。
3. 核对母版保护有效、无业务模型实例，不在母版调用worker的真实`apply`、自动预登记或发证。001的普通worker角色不变，不能沿用旧控制平面阻断规则。

### 实际安装及封版检查

1. 安装已验证的NFS客户端依赖及引导代码、准备统一挂载点和本地缓存路径；按交付清单原子更新文件并核对权限和摘要。保留现有驱动/CUDA、供应商命名和合法的信任初始化流程。
2. 配置稳定服务寻址、受控NFS策略引用和逻辑`image_id`兼容关系；普通worker不得读取管理员发布凭据。保留GPU UUID作为name/external_id及现有自动预登记/发证方式，不部署旧退役插件。
3. 核对systemd单元及timer启用关系；母版只安装/静态检查，不使用`--now`启动worker链，不为测试重启母版或现网VM。必要的真实启动测试在后续独立新VPC完成。
4. 模板保持必要的客户端配置与信任材料，但不包含某台worker的实际GPU UUID、原生token、设备私钥/设备证书、已签发许可、会话状态、applied/maintenance记录或Registry发布认证。不得从运行worker整体复制状态目录进入母版。
5. 确认没有仍运行的试验容器、试验NFS挂载或身份/认证残留；不预装全部模型权重，不把挂载会话当作克隆已经具备自动挂载的证据。
6. 出具“可制作快照”交接清单；在实际安装清单及保护检查完成前，不通知管理员保存原样快照作为本次新版。

### 管理员平台操作与版本登记

管理员在平台保存新版快照，按已核对的供应商流程将其指定给独立VPC A/B，并创建、首次启动这些测试实例。至少分开登记：

| 标识 | 含义 |
| --- | --- |
| Git提交 / 交付包SHA | 客户端及单元的实际软件版本 |
| 逻辑`image_id` / 配置revision | Bootstrap兼容与签名发布范围 |
| 平台snapshot ID / image版本 | 供应商实际保存、选择和应用的快照 |
| 模型库manifest / 模型revision | NFS中实际发布的文件版本 |

不能把更新逻辑`image_id`、保存本地tar包或平台显示相同备注当作新版快照已应用。管理员交付A/B与真实快照版本关联、GPU分配信息及安全访问方式；原始连接信息、凭据、设备/启动标识留在私有证据中。

更新母版或保存快照本身，不作为已经运行的存量VPC已更新的证据。先核对平台生效规则；本计划的新快照应用首先面向明确选定该版本的新VPC，存量节点另走维护迁移。

## 新快照首启与故障验收

首启证据采集前不手工运行mount、bootstrap apply或复制权重。记录供应商命名完成、系统基本启动、延后任务、配置获取、NFS挂载、GPU UUID许可和worker Ready的实际时序。若人工恢复后成功，保留首次失败，不能改写为零干预首启成功。

- **独立性与继承**：A/B确实使用指定的新快照；各自GPU与身份关联正确，未携带母版或另一节点状态。两节点并行证明需不同实际GPU，不能把同卡交替实例作为双卡容量。
- **三层存储**：宿主、worker和模型容器均读取相同NFS版本；真实文件摘要匹配，服务器拒写、容器拒写、本地缓存可写。缺失/错误挂载不触发本地空目录降级。
- **真实调度与请求**：使用隔离测试部署和明确选择器，确认GPUStack实际把实例部署到目标worker；每节点先做1次单页、1次3页固定样本任务，核对结果及页收据。没有执行实例时，worker Ready不算模型服务验收通过。
- **有限并发与资源**：在单节点通过后做两节点有限加载，测NFS网络/磁盘和冷加载耗时，复用当前受控启动并发策略，不直接扩大到全部worker。
- **异常和恢复**：仅在试验export/试验节点验证NFS不可达、错误来源、只读拒写、版本不完整、配置不兼容及恢复后接续；不停止共享NFS来影响其他服务。记录未完成I/O/活动，不盲目重放或清空UNKNOWN。
- **幂等和既有链路**：重复手动apply不重复挂载、不创建第二个worker；Registry、GPU UUID预登记、母版保护及旧本地模式仍符合现行约定。
- **镜像兼容**：至少核对一个内置权重模型和一个NFS权重模型，分别证明实际加载来源及回退行为。NFS版本缺失时不自动读取镜像内置版本；不能以API模型名相同代替代码/权重版本一致性验证。只读模型目录与本地可写缓存分离；继续按现行NFS启动准入执行，不据内置模型存在而自动绕过挂载失败。

启动失败时停在当前阶段，保存故障、尝试次数及现场；不得通过重启XZ-31-001/002、切系统或恢复镜像“修复”。需要再次首启时，由管理员另行提供获准的新建可销毁实例，不操作受保护VM。

## 分批应用、存量迁移与回退

1. 新快照首启门槛通过后，管理员先对小批新VPC指定该快照；我们核对实际文件版本、NFS和服务行为，再推广后续批次。不得仅因管理员已选择快照就记为应用验收通过。
2. 存量worker先确认现有可用副本和容量，按当前已具备的维护边界排空，再更新引导及容器挂载布局。不能假定尚未交付的逐worker无损排空已经存在；若只能影响整个受控模型入口，应明确维护窗口及影响。
3. 不直接在运行实例使用的模型根目录上覆盖NFS挂载。保留原本地权重、配置、镜像和身份备份；只在目标进程/容器范围应用，经三层挂载、身份、实际推理和计量核对后恢复流量。
4. 模型版本回退引用已校验的旧目录；软件回退使用本阶段旧包及配置；母版/快照发布失败时保留旧快照供后续新实例使用。存量VM的软件回退不通过平台还原快照实施。
5. 对引用中的权重和回退目录保留保护。旧OCR改为外部ONNX路径后单独做结果回归；目标范围内仍有模型使用镜像内权重时，记录部分迁移，不能宣布全模型集中完成。

XZ-31-001、XZ-31-002全程禁止整机重启、重建/还原、切系统等等效操作。它们若参与存量维护，也仅按现有允许的进程/容器操作执行；没有做的整机验证不写为已完成。

## 最终交付

发布可追溯的服务端配置、模型清单及哈希、客户端交付包、母版安装清单、平台快照关联、A/B首启与推理证据、小批/存量迁移记录，以及管理员发布/回退/回收和备份恢复手册。证据中区分计划、已安装、已保存快照、已应用、已验收，逐阶段更新Issue #6。

本计划不承诺未经实测的网络带宽、千节点同时加载性能、存储高可用、百页推理或CPU性能。新PC的磁盘和网络仍是共享依赖；阶段1先确定实际能力和边界，再冻结实施参数。

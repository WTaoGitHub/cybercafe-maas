参数实现位于`maas_bench/contracts.py`，CPU/GPU实际容量仍由后续测量确定。扩缩容保留维护锁、暂停排空、generation/UNKNOWN检查及真实探针恢复，新增Qg/Qp时要求成对且项目不超过全局，并统一检查API/执行器/observer。没有扩缩正式环境。

旧`benchmark_executors.py`和`replica_capacity_matrix.py`已支持更多有界参数，仍属于固定数量比较工具，不能作为新计划要求的持续供给证明。新饱和工具通过独立验证前不进入T1/T2正式测量。

新`maas_bench/saturation.py`使用有界补量；`backend.py`只读持久连接观察已提交的数据库状态，不创建常驻collector。输入预先准备，正式窗口不下载结果，结束后排空并核对一次attempt/计量及结果文件。采样周期不超过100ms，超出采样空窗预算或观测断粮即作废，不拼接忙碌片段、不自动重开。离散采样不能证明任意时刻非空，结果中明确`continuous_occupancy_proven=false`。

独立测试只复用带有专用标签的测试PostgreSQL容器、临时非GPU测试容器和模拟模型，没有修改正式应用/副本/额度，也没有调用OCR。首次测试容器因私有挂载目录权限未启动pytest，第二次发现测试夹具使用默认3次重试而非本实验要求的1次；修正测试环境/夹具后两项通过，未改生产重试策略。后续D项高并发多进程验证也已完成，见上表。

依据：[计划](E3-TUNING-PLAN.md) · [设计矩阵](E3-TUNING-MATRIX.json)。每个独立功能验证后单独提交并push；后续进展追加到本记录。

操作入口和私有配置格式见[工具说明](E3-TUNING-TOOLS.md)。原生预备请求、独立到达时钟已有有界实现及本地验证；T1/T3/T4完整在线案例编排、候选选择和长时T6驱动随对应阶段集成。矩阵选择不等于这些阶段已经在线执行。当前异步单点入口不改变参数；恢复前fence返回的是原始运行快照，实际变更/恢复沿用带维护窗口的控制工具，异常不自动恢复。

补充兼容性回归：旧固定数量混合工具读取实时E/G/P，支持有界同步客户端数和请求数，分别核对全局/项目的同步异步共享额度，沿用受理/拒绝/唯一事件检查；它仍不作为持续饱和证据。预上传OCR清单识别`image.artifact_id`，结果下载核对revision/attempt/usage。相关本地测试累计89项通过；不执行旧混合脚本的线上负载。

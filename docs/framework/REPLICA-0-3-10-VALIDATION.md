## 操作与阶段放行

保留当前策略、写入授权和三个部署。副本数由调节器与 GPUStack 自然收敛。旧 worker 记录可保留用于追溯。管理员只操作推理 worker VPC，留新 PC、配置服务、仓库、NFS 和独立管理通道在线。全部关机会中断推理，管理员选择业务可中断的时刻，并记下每批实际操作时间及使用的快照标识。

| 阶段 | 管理员操作 | 测试方观察及放行条件 |
| --- | --- | --- |
| 1 · 现状 → 0 | 关停**全部**推理 worker VPC，包括可能尚未注册或心跳已失联的机器。先只做这一批。 | 核对平台关机完成时间。集群连续 2 分钟无 Ready worker，调节器可用 GPU 为 0，在线节点上的健康副本为 0，控制端仍能取到完整新鲜快照。记录离线判定延迟、三个部署的期望数及遗留实例。满足后通知启动首批 3 台。 |
| 2 · 0 → 3 | 同一最新版快照只启动 3 台。 | 3 个独立启动实例自动注册到目标集群、都有可识别 GPU；核对容器运行时和实际副本。记录每个模型首次 Ready、每笔自动写入及其读回。三模型各有健康副本，在实际显存许可下收敛：没有持续阻塞的新 Error 或无解释 Pending，没有未决写入，连续 2 分钟状态稳定。如果缺节点、模型起不来或应扩未扩，停在 3 台排查，再加 7 台须等本阶段明确放行。 |
| 3 · 3 → 10 | 收到放行后，用同一快照再启动 7 台。 | 验证原有 3 台仍在线，新增 7 台均自动加入，10 台持续 Ready。按每笔新增写入追踪到具体实例 Ready；核对单卡显存余量、在途上限、原有健康副本及分发压力。三个模型到达当前资源与策略允许的目标，连续 2 分钟无未解释的 Pending、Error、启动卡住或未决写入，才记十节点通过。若只到 8 或 9 台，仅记录实际达到的阶段。 |

- **零节点时的副本数。** 关机后界面可暂留旧 Running、Unreachable、Pending 或 Error。若持续确认为资源不足，观察满 180 秒、写入前再确认，允许下调到健康数与策略保底两者中的较大值。当前三模型保底各 1。全关时 0/1 是合法结果；无需手动清成 0/0。没有形成该类 Pending 时，按实际原因记录。若首批立即上线打断 180 秒观察，该分支记为未验证；要验证它，先等本轮观察窗口结束。
- **配额与启动顺序。** 同时缺少保底时，启动优先级为 Unlimited → Ovis → PP；其后按 1:2:4 权重和单卡可放置条件规划。不同 GPU、显存碎片、原生已有 Pending 都可能改变最终数量与 Ready 先后。若某模型连一个副本都放不下，记录申报值、可用显存和阻塞原因，标为“容量不足，三模型健康门槛未达”，停在该阶段。
- **区分是谁恢复了服务。** 关机前已有的期望数在新 worker 上兑现，计为 GPUStack 原生调度；期望数变化与调节器日志写入和读回匹配，才计为调节器动作。报告分别给出两者的数量与耗时。若 0→3 只兑现旧目标且实际无扩容空间，记录此事实；3→10 如有可行增量却无调节动作，不能验收通过。

## 取证与暂停条件

1. 在新 PC 上使用现有[只读观测脚本](../../scripts/maas/runtime/observe_replica_startup.py)，建议每 5 秒取一次，按阶段有界续采；[采集命令和计数器](REPLICA-STARTUP-OBSERVATION.md#同一时间轴的指标)可直接复用。将管理员动作时间、快照版本、GPUStack 首见/Ready、调节器写入/读回、分配 worker、首次 Running 及稳定时刻记在同一时间轴。各阶段取最后连续 120 秒完整样本；采样缺口不计入稳定时长。
2. 以该批平台启动记录、worker ID、GPU UUID 及可读的启动 ID 关联新克隆。名称、IP 和 GPU UUID 都可能被复用；同 UUID 再次上线可属正常，须去重核对同时在线的卡。无法取得启动 ID 时，保留平台批次和控制端注册时间的交叉证据，并注明限制。新快照克隆并不保证无缓存，仅在能证明未命中并观察到真实拉取或读权重时才报冷启动耗时。
3. 按模型保存 `运行/期望`、实例生命周期、写入前后值、在途及隔离原因；按节点记录可分配显存、申报、保留量。扩容阶段同步取分发队列字节差、丢包、NFS 读字节与磁盘等待。记录从首次新增 GPU 可用到各模型首个新增副本 Ready、全部收敛的耗时。采不到的计数标为缺测。
4. 写入结果未知时只读核对；证实写入未发出且为临时故障，才允许调节器退避并按最新状态重算。故障复发先保留新实例 ID、宿主、时间、容器 ExitCode/OOM 和相邻内核日志。只能读取控制端时注明证据缺口。若调节器持续无进展、重复写入、控制面失联或某批未过门槛，暂停下一批，保留现场。测试方不重启节点、不人工改副本、不向既有业务补发请求。

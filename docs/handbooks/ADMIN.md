# 管理员用户手册

> **2026-10-29角色约定**：当前业务开通对象为下游服务，最终用户/用户Key/用户限流和收费由下游负责。MaaS按服务凭据映射到项目，保留共享容量与存储保护；不要求为下游每个最终用户建Key/project。当前实际4执行器、并发4/4，详细交付口径见[接入与容量约定](../framework/SERVICE-ACCESS-POLICY.md)，接口及限额以[当前API](../api/README.md)为准。本次未部署或更改既有绑定。

> E6迁移说明（2026-10-22）：正式版本e6-r1已上线，已移除同步/异步推理的动态preflight门禁，改为静态模型/revision登记并复用GPUStack服务状态。下文collector、30秒证明与MAAS_TRUSTED_DIR相关说明属于旧P2–P4基线；新部署不安装collector、不挂载consumer导出，维护/备份恢复使用真实业务探针。当前正式发布状态及操作以 [E6执行记录](../framework/E6-RETIREMENT.md) 为准。鉴权、配额、UNKNOWN和成功计量规则保留。


面向业务/平台管理员，基线为2026-10-21当前私有OCR系统，不包含E1。涉及宿主机文件、部署或维护的步骤由具备权限的运维执行，不要求普通用户拥有这些权限。

## 1. 你可以管理什么

| 功能 | 当前入口/能力 |
|---|---|
| GPUStack用户、推理key、模型/路由权限 | GPUStack v2.2.3管理界面/受信任管理工具 |
| worker、模型部署、实例状态、GPU观察 | GPUStack管理界面；变更前与运维确认固定版本/维护范围 |
| MaaS project及逻辑模型授权 | 私有bindings.json与catalog.json，由运维受控修改 |
| 服务并发、队列、存储及TTL | 私有app.env统一配置，由运维在窗口应用 |
| 成功用量与本地告警 | 私有CLI/指标与看板，由运维导出给授权管理员 |
| 维护、备份、恢复、回退 | 宿主机操作流程，见运维手册 |

没有独立MaaS管理员网页、客户自助注册/找回密码、客户密钥门户、项目管理API、套餐充值/扣费或账单下载。GPUStack账号不自动获得MaaS访问资格。

## 2. 管理界面与客户入口的区别

GPUStack UI经授权SSH转发001的18080访问，实际账号/口令由管理员保管；不依赖已不存在的初始密码文件。管理key只供控制面，不交给用户、不挂到API/执行器。

客户使用MaaS私有18832入口和逻辑模型 `ocr.default`。原生GPUStack路由名（例如rapidocr-gpu或另一个已登记固定版本路由）不直接等于客户模型名。

Playground可做人工诊断：进入Chat、选对应原生OCR路由、上传一张PNG/JPEG、发送“提取文字”。已部署适配层支持识别结束后SSE返回文字；不是边识别边出字，也没有语言理解/对话能力。

**Playground不经过MaaS任务系统**：没有MaaS任务ID、输入/结果TTL、统一队列、取消或MaaS成功计量保证。客户受控同步入口只支持stream=false。不要用Playground可用来代替整个异步链路可用的验收；维护前须停止管理侧旁路推理。

## 3. 为下游服务开通OCR

1. 确认用户需要普通文字提取；当前不提供PDF直接处理、视频、图像生成或用户批处理门户。
2. 在GPUStack准备非管理员推理身份与API key，限制到实际批准的OCR上游路由，并设置到期时间；确认GPUStack原生模型访问检查通过。
3. 确定MaaS project归属。不同客户需要资源隔离时使用不同project；同project内资源是共享的，不是按个人账号隔离。
4. 将key通过安全文件方式交给运维，登记credential ID、project和 `ocr.default`允许清单。不要发在工单正文、聊天或Git里。
5. 运维以UID10001可读的私有文件部署key和bindings，保持原有secret，校验目录/文件权限与无重复绑定。
6. 用新key分别验证允许的模型、同步/异步成功、异项目资源拒绝、超额响应，再交付用户。

当前登记结构示例（不是可直接覆盖正式文件的整份配置）：

```json
{
  "credentials": [
    {
      "id": "customer-a-key-1",
      "project": "customer-a",
      "enabled": true,
      "secret_file": "/run/secrets/customer-a-key",
      "models": ["ocr.default"]
    }
  ]
}
```

`secret_file`是容器内路径，对应宿主机正式secrets目录下文件。正式secret目录UID10001/700，文件UID10001/600；绑定文件也必须私有。示例的客户不是已经存在的用户；修改时合并保留已有合法条目，原子替换，不能把示例覆盖线上。

一个key不能同时登记到多个project；credential ID和key指纹都必须唯一，否则整个绑定校验会拒绝。请求的 `X-Project`/`X-User-ID`不能改变身份；仅把project写进请求也不会创建项目。

## 4. 下游接入交付清单

交付：

- 已批准的访问方式、私有API base URL、可信公共TLS证书；不要给root SSH或TLS私钥。
- 受限推理key及有效期，通过安全渠道交付，指导用户文件权限600。
- 允许逻辑模型 `ocr.default`、图片/请求大小限制、额度与总截止时间含排队的说明。
- 输入/结果默认24小时保留、结果需及时下载；项目内共享资源的说明。
- 同步超时/UNKNOWN不盲目重发、维护期全局影响和支持联系渠道。
- [普通用户手册](USER.md)及测试图片；不要用未授权敏感图片做开通验收。

当前所有访问为私有试点，公网域名和公有CA证书未交付。UI的admin权限不是客户使用条件。

## 5. 授权变更、禁用与轮换

bindings每次校验重新读取；设置enabled=false/撤销登记后，新校验会拒绝，执行器也会在任务执行前重新校验凭据。它不强行终止已经发送的GPU请求；排队任务可能因凭据撤销失败。GPUStack侧撤销与MaaS本地禁用应一并核对，旧key不得保留原生旁路权限。

轮换建议：先发新key并以新的credential ID登记到同一project/模型 → 验证新key → 用户迁移 → 处理旧credential排队任务 → 撤销GPUStack旧key及本地绑定 → 确认旧key拒绝。不能随意修改旧credential的project来“迁移账户”，这会影响已接纳任务执行权限。

当前试点key有效期30天，需要第29天前人工轮换；没有自动轮换。TLS证书也需由运维到期前更新。禁用和过期不是任务取消接口，必要时由用户取消已知排队任务，运行中任务按维护/未知执行流程处理。

## 6. 模型目录与版本管理

客户仅知道逻辑模型；catalog把它绑定到driver、revision、GPUStack路由、预算及受信任证明。上游部署、镜像、backend参数或worker集合改变，可能使pin失效并阻止推理，不能在UI随意改后直接要求应用忽略校验。

增加/变更模型需要开发提供已验证驱动与恢复探针，管理员批准模型权限，运维在受控窗口发布目录/pin/collector与配额。当前正式只有OCR；不能只给bindings增加名字就获得新的运行能力。

已接纳任务保存目录fingerprint，直接改revision/路由/预算等目录字段可能使旧排队任务失败。发布前处理队列、准备备份和回退，不覆盖原不可变pin。变更集群模型集合还会使当前维护绑定拒绝执行，必须重新审查维护范围。

## 7. 配额、用量与服务承诺

当前同步与异步共用默认全局并发2、每project1，异步由单执行器执行。等待队列默认1000/每project100；实际配置由运维确认。没有每project独立套餐额度，所有project采用同一项目上限参数。

异步每个成功任务计一次；同步每个服务端成功请求计一次，客户端重复同步请求可能再次计成功。失败/取消/维护探针不产生成功用量；UNKNOWN不是可随意重做的普通失败。私有用量CLI可供授权管理员统计，但没有时间段账单页面、商业价格、发票或自动扣款。

计量不表示客户端已收到结果，也不是GPU耗时、电量或真实token。现有吞吐/成本试验报告仅供容量评估，不自动成为对客户的SLA。8小时耐久、短时4客户端测试和最大吞吐分别评估，不能混称。

## 8. 维护公告与问题处理

当前维护会暂停受控推理并将整个目标集群模型副本归零，其他模型/worker不会自动持续服务。异步请求可能被有界受理但继续等待并消耗总deadline；普通用户应避免维护期提交。

出现故障时，收集request ID、task ID、时间、逻辑模型、HTTP/error.code；不要收集用户API key。UNKNOWN交给运维核对后台结束证据，不能从管理UI随意重放。输入/结果过期不保证找回，按保留约定及备份时点评估。

[运维手册](OPERATIONS.md)负责实际操作；本手册的权限与额度描述不能覆盖运维安全判定。
